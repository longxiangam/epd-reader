# 第 7 篇：低功耗设计与电源管理

> English: [en/07-low-power-and-power-management.md](en/07-low-power-and-power-management.md)

> 用 Rust 构建ESP32-C3 电子墨水屏阅读器 · 系列文章

## 引言

电池供电是嵌入式设备最基本的需求之一。本项目使用一块锂电池供电，ESP32-C3 在 WiFi 开启时功耗约 80-100mA，而深度睡眠时仅 5-10μA——差了四个数量级。

如何让用户在两次充电之间使用尽可能长的时间？答案有两个：一是利用电子墨水屏"断电不丢失"的特性，二是精心设计睡眠策略。本文将覆盖深度睡眠、RTC 内存、外设电源控制、电池管理等关键技术。

## 1. 深度睡眠

### 1.1 睡眠触发条件

所有页面都通过 `to_sleep_tips` 进入睡眠，它有两个关键参数：

- `sleep_time`：定时唤醒时长。大于 0 表示"刷完这帧后睡这么久再醒来刷新"（布防 PCF 定时唤醒）；等于 0 表示只按空闲时间或按键唤醒。
- `idle_time`：空闲多久才算"没人用"，超过才允许入睡。

主循环中，每 5 秒检查一次空闲时间。如果超过 180 秒（3 分钟）没有任何操作，就进入睡眠：

```rust
// src/main.rs:392-398（主循环中）
to_sleep_tips(
    Duration::from_secs(0),
    crate::sleep::idle_for(Duration::from_secs(180)),
    true,
).await;
Timer::after(Duration::from_secs(5)).await;
```

`idle_for` 是空闲阈值的一层包装：定时唤醒后的数据刷新窗口期内，它返回 3600 秒——窗口内永不满足空闲条件，由"立即回睡"捷径接管（见 1.5）。

页面级别的睡眠时间各不相同：

```rust
// src/pages/main_page.rs:282（主菜单）
to_sleep_tips(Duration::from_secs(0), crate::sleep::idle_for(Duration::from_secs(30)), true).await;

// src/pages/read/page.rs:2554-2568（阅读中，空闲阈值可配置，默认 120 秒）
to_sleep_tips(Duration::from_secs(0), Duration::from_secs(read_sleep_seconds), true).await;

// src/pages/stock/page.rs:614-619（股票页，sleep_time>0 → 定时唤醒）
to_sleep_tips(
    Duration::from_secs(sleep_secs),
    crate::sleep::idle_for(Duration::from_secs(idle_secs)),
    true,
).await;
```

- 主菜单 30 秒无操作就睡眠；阅读页面可配置（默认 120 秒，最小 10 秒，步进 5 秒）。
- 天气/日历页的定时唤醒周期见 5.3；股票页按交易时段决定（开盘 120 秒，非开盘睡到下一开盘）。
- 阅读菜单选"睡眠"时传 `idle_time=0`，立即入睡。

### 1.2 睡眠流程

`to_sleep_tips` 是睡眠的入口函数：

```rust
// src/sleep.rs:73-171（简化）
pub async fn to_sleep_tips(sleep_time: Duration, idle_time: Duration, show_sleep: bool) {
    // 定时唤醒的数据刷新窗口内不放行睡眠（等 WiFi/天气/AHT20 就绪）
    if timed_hold_off() { return; }

    // 定时唤醒且用户没碰过按键：刷新+渲染已完成的页面 → 立刻入睡（见 1.5）
    let immediate = unsafe { TIMED_WAKE && !USER_TOUCHED && sleep_time.as_secs() > 0 };
    if !immediate {
        if *LAST_ACTIVE_TIME.lock().await == Instant::MAX { return; }
        if Instant::now().duration_since(*LAST_ACTIVE_TIME.lock().await) <= idle_time { return; }
    }

    if immediate || Instant::now().duration_since(*LAST_ACTIVE_TIME.lock().await) > idle_time {
        // 1. 停止 WiFi
        force_stop_wifi().await;

        // 2. 配置唤醒源：GPIO 按键 + PCF/RTC 定时器
        let wakeup_pins = unsafe { core::ptr::addr_of_mut!(WAKEUP_PINS).as_mut().unwrap() };
        let rtcio = RtcioWakeupSource::new(wakeup_pins.as_mut_slice());
        let mut ws: Vec<&dyn WakeSource, 2> = Vec::new();
        ws.push(&rtcio);
        // ... PCF 布防分档（见 1.3），布防失败自动退回 ESP RTC 定时唤醒

        // 3. 显示待机画面（电子墨水屏的亮点）
        if show_sleep { crate::display::show_sleep().await; }

        // 4. 等渲染周期结束并排空：异步刷新期间断电会产生发灰残影
        crate::display::await_render_idle().await;

        // 5. 保存当前 RTC 时间戳
        unsafe { *core::ptr::addr_of_mut!(WHEN_SLEEP_RTC_MS) = get_rtc_ms().await; }

        // 6. 断开电源轨（板级差异见第 3 节；空槽 take 出 None 自动跳过）
        if let Some(mut p) = EINK_PWER_PIN.lock().await.take() { p.set_high(); }
        if let Some(mut p) = SD_PWER_PIN.lock().await.take() { p.set_high(); }

        // 7. 保存时间到 RTC 寄存器
        save_time_to_rtc().await;

        // 8. 进入深度睡眠
        RTC_MANGE.lock().await.as_mut().unwrap().sleep_deep(ws.as_slice());
    }
}
```

流程图：

```
空闲超时检测（或定时唤醒的"立即回睡"捷径）
    │
force_stop_wifi() ←── 停止 WiFi（最大省电项）
    │
配置唤醒源 ←── GPIO 按键 + PCF 定时/报警（失败退 ESP RTC 定时器）
    │
show_sleep() ←── 在电子墨水屏上渲染待机画面
    │
await_render_idle() ←── 等面板刷新/睡眠命令走完，防断电残影
    │
保存 RTC 时间 ←── 记录进入睡眠的时间戳
    │
断开电源轨 ←── 屏幕和 SD 卡统一断电
    │
save_time_to_rtc() ←── 将系统时间写入 RTC 寄存器
    │
sleep_deep() ←── CPU 停止，仅 RTC 保持供电
```

注意步骤 3 和 6 的顺序很重要：先在屏幕上显示待机画面，然后才关闭屏幕电源。因为电子墨水屏断电后画面不消失，所以这个画面会一直保持到下次唤醒——这就是"待机画面"的原理。待机画面本身支持定制：渲染任务注册了 `sleep_renderer` 的页面（天气/日历/股票/阅读）用低信息密度版布局画待机帧，未注册的走 flash 分区里的睡眠位图（`flash_sleep::draw_sleep_image`），都没有则退化为"睡眠中"文字。

### 1.3 睡眠布防分档（PCF8563 定时唤醒）

`sleep_time > 0` 时需要布防定时唤醒。定时唤醒改由 PCF8563 硬件 RTC 承担（INT 脚拉低 GPIO4 唤醒 CPU）：PCF 走纽扣电池（CR2032），主控深睡电流更低，且 32k 晶振走时精确——主控深睡慢时钟漂移大，不适合长间隔计时。按睡眠时长分三档：

| 睡眠时长 | 布防方式 | 说明 |
|--------|---------|------|
| ≤255 秒 | PCF 倒计时 1Hz 档（`arm_timer_secs`） | 寄存器 0x0F 装载秒数，精确到秒 |
| ≤255 分钟 | PCF 倒计时 1/60Hz 档（`arm_timer_minutes`） | 分钟数向上取整，最多多睡 59 秒 |
| 更长（有 PCF） | PCF 绝对时间报警（`arm_alarm_at`） | 按 PCF 自身走时（UTC）设定到点时刻 |
| 无 PCF（v1）/ 布防失败 | ESP RTC `TimerWakeupSource` | 自动兜底 |

```rust
// src/sleep.rs:107-141（简化）
let armed = if total <= 255 {
    crate::pcf8563::arm_timer_secs(total as u8).await
} else if total <= 255 * 60 {
    let mins = ((total + 59) / 60) as u8;      // 向上取整
    crate::pcf8563::arm_timer_minutes(mins).await
} else if crate::board::HAS_PCF {
    match crate::pcf8563::read_time().await {
        Some(pcf_now) => crate::pcf8563::arm_alarm_at(pcf_now + total as i64).await,
        None => false,                          // PCF 走时无效 → ESP RTC 兜底
    }
} else {
    false                                       // v1 无 PCF → ESP RTC 兜底
};
if !armed {
    fallback_timer = Some(TimerWakeupSource::new(core::time::Duration::from_secs(total)));
}
```

绝对时间报警写报警寄存器 0x09-0x0C（分/时/日 BCD 比较，星期寄存器写 0x80 禁用比较）并使能 AIE。注意 PCF8563 的报警**没有月份寄存器**：睡眠间隔超过 28 天时，会在次月同日提前唤醒一次——醒来重新布防即可，无害。

`sleep_time = 0` 时不布防任何定时器，只能通过按键唤醒。

### 1.4 唤醒源

ESP32-C3 支持两类唤醒源，两代板都注册：

**GPIO 唤醒**（按键唤醒）：

```rust
// src/main.rs:306-309
// RTC 唤醒键注册：必须在阅读分支之前——阅读模式睡眠(to_sleep_tips/reboot_sleep)
// 也要靠这个 RTC IO 唤醒源，否则睡下唤不醒。
let rtc_io = static_cell::make_static!(crate::board::key_ladder_pin());
add_rtcio(rtc_io, WakeupLevel::Low).await;  // 低电平唤醒（按键按下）
```

唤醒脚是三键梯（ADC 分压区分键号）：v2 新板为 GPIO4，v1 旧板为 GPIO2。按键按下时被拉低，触发 RTC IO 唤醒。v2 板上 PCF8563 的 INT 脚也接在同一个 GPIO4 上——定时唤醒和按键唤醒共用一条唤醒通路，靠 1.6 的分类逻辑区分。

**定时器唤醒**：

PCF 倒计时/报警到点 → INT 拉低 GPIO4（1.3 节）；PCF 缺席或布防失败时退回 ESP RTC 定时器。`sleep_time` 为 0 则不布防，只能按键唤醒。

### 1.5 定时唤醒立即回睡

定时唤醒的本质是"醒来 → 联网刷新 → 重绘 → 再睡"，如果刷新完成后还要再等满 3 分钟空闲时间，设备就白白多亮几分钟。因此 `sleep.rs` 里有条捷径：

```rust
// src/sleep.rs:22-60
static mut TIMED_WAKE: bool = false;      // 本次唤醒是否为定时唤醒
static mut TIMED_HOLD_OFF_UNTIL: u64 = 0; // 数据刷新窗口截止时刻（ms）
static mut USER_TOUCHED: bool = false;    // 定时唤醒后用户是否按过键

/// 实体按键事件（event::run 每次按键）调用。
pub fn mark_user_touch() { unsafe { USER_TOUCHED = true; } }

/// 定时唤醒的数据刷新窗口：窗口内 to_sleep_tips 不放行睡眠
/// ——留给 WiFi 连接/天气时间同步/AHT20 首次采样完成。
pub fn timed_hold_off() -> bool {
    unsafe { TIMED_WAKE && (Instant::now().as_millis() as u64) < TIMED_HOLD_OFF_UNTIL }
}

/// 页面空闲超时：定时唤醒的窗口期内 → 永不满足；否则用页面配置值
pub fn idle_for(default: Duration) -> Duration {
    if timed_hold_off() { Duration::from_secs(3600) } else { default }
}
```

入睡判定：

```rust
// src/sleep.rs:82
let immediate = unsafe { TIMED_WAKE && !USER_TOUCHED && sleep_time.as_secs() > 0 };
```

三个条件同时满足才走捷径：

1. 本次唤醒是定时唤醒（`TIMED_WAKE`）；
2. 用户没碰过任何键（`!USER_TOUCHED`，`event.rs` 的按键任务每收到一次实体按键就 `mark_user_touch()`）；
3. 调用方带 `sleep_time > 0`——说明是"刷新完成"的页面在请求定时回睡。

主循环/主菜单传的 `sleep_time` 恒为 0，永不走捷径，防止误杀同步中的页面。捷径生效时跳过空闲时间检查，刷新+渲染一完成立即入睡；用户碰过键则回退普通空闲流程（想看就多留一会儿）。

刷新窗口（hold-off）只在天气数据过期时启用：main 启动时按 `Weather::weather_stale()` 决定给 8 秒窗口等 WiFi 连接+天气/时间同步，数据新鲜则不给窗口——读完温度立刻就能睡。

### 1.6 唤醒分类与首帧处理

唤醒后程序从 `main()` 开头重新执行（不是从睡眠点继续）。启动早期先做唤醒分类：

```rust
// src/main.rs:179-196
// 深睡唤醒分类：PCF8563 TF=1 → PCF 定时唤醒（PCF INT 拉低 GPIO4）；
// ESP RTC Timer → PCF 布防失败时的 ESP 定时回退唤醒；否则按钮唤醒。
// 读完清标志 + 关定时器（INT 释放，防运行期假按键）
let timed_wake = crate::pcf8563::consume_timer_wake().await
    || matches!(wake_reason, esp_hal::system::SleepSource::Timer);
// 天气数据过期才需要联网刷新（8 秒窗口等 WiFi+同步）；
// 数据新鲜则无窗口：读完温度重绘后立刻回睡
let stale = crate::weather::Weather::weather_stale().await;
crate::sleep::set_timed_wake(timed_wake, if stale { 8_000 } else { 0 });
// 非定时唤醒（按钮/上电）进入程序：首帧强制全刷，清上一会话残影；
// 定时唤醒保持快刷（分钟级唤醒每次全刷会闪烁+耗电）。
if !timed_wake {
    crate::display::mark_need_clear();
}
```

`consume_timer_wake` 读 PCF8563 的 Control_status_2 寄存器判断 TF（倒计时到点）或 AF（报警到点）标志，随后清 TF/AF、停定时器、关 AIE/TIE——定时器不关的话，运行期 INT 拉低 GPIO4 会被按键网络误判成假按键。

分类结果决定两件事：

- **定时唤醒**：设置 `TIMED_WAKE` 与刷新窗口（1.5），首帧保持快刷（分时/分钟级唤醒每次全刷会闪烁+耗电）。
- **非定时唤醒**（按钮/上电）：`mark_need_clear()` 强制首帧全刷，清掉上一会话留在面板上的残影。

### 1.7 重启分模式：reboot_sleep

"切换运行模式"（进入/退出阅读）也用深度睡眠完成，但只睡 50 毫秒：

```rust
// src/sleep.rs:180-199（简化）
pub async fn reboot_sleep() {
    let rtcio = RtcioWakeupSource::new(wakeup_pins.as_mut_slice());
    let timer = TimerWakeupSource::new(core::time::Duration::from_millis(50));
    let mut ws: Vec<&dyn WakeSource, 2> = Vec::new();
    ws.push(&rtcio);
    ws.push(&timer);
    crate::display::await_render_idle().await;   // 同 to_sleep_tips：切电前确保面板空闲
    // 电源轨断电（同 to_sleep_tips）
    ...
    RTC_MANGE.lock().await.as_mut().unwrap().sleep_deep(ws.as_slice());
}
```

深睡唤醒会重新跑 `main`（重新决定起不起 WiFi、重新分配堆），且**保留 rtc_fast**（模式标志/书索引/续读偏移），所以模式切换不需要 `software_reset`——那会把 rtc_fast 清空。主菜单选"电子书"时置阅读标志 + 写 NVS 哨兵，`reboot_sleep` 50ms 后唤醒的 `main` 检测到标志直接进阅读模式（不初始化 WiFi，独占整块堆做 TTF 渲染）；退出阅读同理切回正常模式。

## 2. RTC 快速内存

RTC 快速内存是 ESP32-C3 上一块特殊的 SRAM（约 8KB），在深度睡眠期间保持供电。放在这里的变量在唤醒后仍然保留上次的值。

```rust
// src/display.rs:49-50
#[ram(unstable(rtc_fast))]
static mut RENDER_TIMES: u32 = 0;
```

本项目中的 RTC 变量（节选）：

| 变量 | 文件 | 用途 |
|------|------|------|
| `RENDER_TIMES` | display.rs | 快刷计数（决定何时全刷） |
| `NEED_CLEAR` | display.rs | 冷启动清屏标记（首帧强制全刷） |
| `LAST_BATTERY_PERCENT` | battery.rs | 上次电池电量 |
| `WHEN_SLEEP_RTC_MS` | sleep.rs | 入睡时的 RTC 时间戳 |
| `PAGE_INDEX` / `BOOTED` | main_page.rs | 主菜单选中项 / 冷启动标记 |
| `READING_MODE` / `PAGE_INDEX` / `TTF_RESUME_OFFSET` | read/page.rs | 阅读模式标志 / 书下标 / 续读字节偏移 |
| `RESUME_SUBDIR` / `LIST_SUBDIR` / `LIST_BOOK_IDX` | read/page.rs | 续读子目录 / 书单层与书下标记忆 |
| `STOCK_MODE` / `STOCK_VIEW` / `STOCK_MINUTE_CACHE` | stock/page.rs | 股票图模式 / 视图 / 6 支分时缓存 |
| `WHEN_SLEEP_TIME_TIMESTAMP` 等 | worldtime.rs | 时间恢复与同步标志 |
| `RTC_FAST_BOOT_SEQ` | board/mod.rs | 诊断：启动序号自增 |

### RTC 内存的使用模式

```rust
// 写入
unsafe {
    *core::ptr::addr_of_mut!(WHEN_SLEEP_RTC_MS) = get_rtc_ms().await;
}

// 读取
pub async fn get_sleep_ms() -> u64 {
    get_rtc_ms().await - unsafe { *core::ptr::addr_of!(WHEN_SLEEP_RTC_MS) }
}
```

唤醒后，通过 `get_sleep_ms()` 计算睡眠了多长时间，加上睡眠前的系统时间，就能恢复当前的时钟——不需要每次唤醒都做 NTP 同步（v2 板上时钟恢复优先走 PCF8563 硬件时钟，见 5.3）。

### rtc_fast 会丢的两种情况

- **software_reset**：软复位会清 rtc_fast。这就是 1.7 的模式切换用 `reboot_sleep`（深睡）而不是软复位的原因。
- **v2 板的 RTC IO 唤醒**：实测 IO（RTCIO）唤醒会丢 rtc_fast 状态（`BOOTED=false`、阅读标志丢失）。关键状态因此都落了一份 NVS 哨兵：页面变化时写 `write_sleep_page`，唤醒后 `read_sleep_page` 恢复最后所在页；"上次在阅读"由哨兵值 `PAGE_READING` 标记，main 启动时据此直接进阅读模式。

另有开机自增的 `RTC_FAST_BOOT_SEQ` 诊断：跨深睡唤醒保持递增 = 保留正常；归 1 = 深睡中丢了。

## 3. 外设电源控制（电源轨）

ESP32-C3 本身没有为每个外设提供独立的电源域，但本项目通过 GPIO 控制外部 MOSFET 实现屏幕/SD 卡断电。两代板的电源轨不同：

| 板型 | 电源轨 | 极性 | 睡前动作 |
|------|--------|------|---------|
| v1 旧板 | 双轨：EINK=GPIO21 / SD=GPIO1 | 高电平=断电 | 两轨都置高断电 |
| v2 新板 | 单轨：GPIO1 | 低电平=开启 | 置高断电 |

```rust
// src/board/v1.rs:39-49（v2 的 init_power_rails 把两个槽填同一根 GPIO1）
pub async fn init_power_rails(p: &mut Peripherals) {
    let mut eink_pwr_ctrl = Output::new(p.GPIO21, Level::High, OutputConfig::default());
    let mut sd_pwr_ctrl = Output::new(p.GPIO1, Level::High, OutputConfig::default());
    eink_pwr_ctrl.set_low();   // 低电平 = 开启电源（MOSFET 导通）
    sd_pwr_ctrl.set_low();
    crate::sleep::EINK_PWER_PIN.lock().await.replace(eink_pwr_ctrl);
    crate::sleep::SD_PWER_PIN.lock().await.replace(sd_pwr_ctrl);
}
```

睡眠侧不感知板型：`to_sleep_tips` 把 `EINK_PWER_PIN`/`SD_PWER_PIN` 两个槽 `take` 出来统一置高，空槽自动跳过——v1 是两路物理轨，v2 是同一根轨填两个槽，效果等价。

**为什么深睡前必须断轨**：带轨入睡（GPIO1 保持驱低）会在唤醒瞬间拉塌电池轨，触发 POR——rtc_fast 全部丢失。所以 `to_sleep_tips`/`reboot_sleep` 都在 `sleep_deep` 之前断轨，唤醒后 main 重新上电。

**pad hold 的板级差异**：

```rust
// src/board/v2.rs:24-28：开机释放上次深睡布下的 hold（RTC 域跨深睡保留——
// 不释放的话 GPIO1 的驱低上轨写不进去 → 轨断电 → 显示/SD 全灭）
pub fn init_pad_hold(_p: &mut Peripherals) {
    esp_hal::peripherals::LPWR::regs().pad_hold().modify(|_, w| unsafe { w.bits(0) });
}

// src/board/v1.rs:25-28：旧板给 GPIO1(SD 轨) 打 hold（深睡中保持轨状态）
pub fn init_pad_hold(p: &mut Peripherals) {
    unsafe { p.GPIO1.clone_unchecked() }.rtcio_pad_hold(true);
}
```

**GPIO2 深睡隔离**（v2 板，电池分压脚）：

```rust
// src/main.rs:244-258
// GPIO2 是 strapping 脚，硬件复位默认带内部上拉——深睡数字域掉电后 pad 若
// 回退到复位默认，会把分压中点（VBAT/2≈1.7V）抬到 ~3V，徒增漏电。显式
// sleep 配置在 RTC 域，深睡中强制高阻。
let io_mux = esp_hal::peripherals::IO_MUX::regs();
io_mux.gpio(2).modify(|_, w| {
    w.slp_sel().set_bit();      // 深睡走 sleep 配置
    w.mcu_ie().clear_bit();     // 关输入
    w.mcu_wpu().clear_bit();    // 关上拉
    w.mcu_wpd().clear_bit()     // 关下拉
});
```

运行期 pad 仍走模拟配置，ADC 采样不受影响；这些位开机设一次终身有效（`set_analog` 与隔离代码互不触碰）。

## 4. WiFi 省电策略

WiFi 是最大的功耗来源。项目实现了自动关闭机制：

```
使用网络 → use_wifi()（加锁 + 刷新时间戳）
     │
完成 → finish_wifi()（解锁）
     │
do_stop 任务每 3 秒检查一次
     │
30 秒内没有新的网络请求？
     │
Yes → STOP_WIFI_SIGNAL → 断开 WiFi → WifiStopped
     │
下次需要网络时 → RECONNECT_WIFI_SIGNAL → 重新连接
```

这样，WiFi 只在实际需要时才开启。设置页的 web 配置服务运行期间会周期性调用 `refresh_last_time()` 保活，避免配置到一半被自动断网。

## 5. 网络同步的定时策略

### 5.1 ntp_worker 的定时策略

`ntp_worker` 是所有网络同步的调度中心。它的主循环间隔决定了网络请求的频率：

```rust
// src/worldtime.rs:417-482（简化）
loop {
    let mut sleep_sec = 3600;  // 默认 1 小时

    // NTP 同步：距上次同步超过 1 小时，或从未同步过
    if now - sync_time_second > 3600 || sync_time_second == 0 {
        match use_wifi().await {
            Ok(stack) => match ntp_request(stack, clock).await {
                Ok(_) => {
                    // 对时成功 → 写入 PCF8563（备电池维持，唤醒/断电不丢）
                    crate::pcf8563::write_time(ts).await;
                    sleep_sec = 3600;            // 成功：1 小时后再同步
                }
                Err(_) => { sleep_sec = 1; }     // 失败：1 秒后重试
            },
            Err(_) => { sleep_sec = 10; }        // 断网：退避重试，避免空转耗电
        }
    }

    // NTP 同步成功后，触发天气和节假日同步
    if sync_time_success() {
        Weather::sync_weather().await;
        HolidayInfo::sync_holiday().await;
    }

    Timer::after(Duration::from_secs(sleep_sec)).await;
}
```

### 5.2 天气与节假日同步

天气同步的间隔由 `Weather::sync_weather()` 控制：

```rust
// src/weather.rs:158-166（简化）
pub async fn sync_weather() {
    // 首次启动，从 Flash 加载缓存的时间戳
    if WEATHER_SYNC_SECOND == 0 { Self::get_weather().await; }

    // 距上次天气同步超过 5 小时，才发起新请求
    if !sync_weather_success() || now - WEATHER_SYNC_SECOND > 3600 * 5 {
        let _ = Weather::request().await;
    }
}
```

实际的同步间隔：

| 同步项 | 间隔 | 说明 |
|--------|------|------|
| NTP 时间 | 1 小时 | `ntp_worker` 主循环 3600 秒 |
| 天气数据 | 5 小时 | `3600 * 5 = 18000` 秒 |
| 节假日 | 1 年 | 检查年份是否变化，变化时重新拉取 |
| NTP 失败重试 | 1 秒 | 连续失败 5 次后降为 10 秒 |
| 断网（拿不到 stack） | 10 秒 | 退避重试，空闲 180 秒后照常入睡 |

WiFi 在每次同步完成后立即通过 `finish_wifi()` 释放，进入 30 秒倒计时自动关闭。以 5 小时一次天气更新计算，WiFi 每天只开启约 5 次，每次几秒。

### 5.3 各页面的定时唤醒周期

定时唤醒周期（1.3 的 `sleep_time`）由当前页面决定：

| 页面 | 定时唤醒周期 | 说明 |
|------|-------------|------|
| 天气/日历 | 时间显示开：对齐下一分钟边界（≥空闲阈值） | 唤醒即分钟跳变，整点换面 |
| 天气/日历 | 时间显示关：睡到天气数据过期（`stale_in_secs`，至少 60s） | 与 5 小时同步间隔一致 |
| 股票（开盘） | 120 秒 | 交易日 9:15~11:31 / 12:55~15:01（含集合竞价，端点留 1 分钟余量） |
| 股票（非开盘） | 睡到下一开盘时点 | 午休→当日 12:55；收盘/周末/节假日→次交易日 9:25（节假日数据感知，扫 30 天兜底 12h） |
| 股票（日K/周K/月K） | 12 小时 | 非实时模式 |
| 阅读 | 无定时唤醒 | `sleep_time=0`，只按键唤醒 |

v2 板上 PCF8563 同时是系统时钟源：NTP 对时成功后把 UTC 时间写入 PCF（CR2032 维持），每次唤醒优先从它恢复——深睡漂移、阅读模式无 WiFi、断电换电池都不再丢时间。阅读模式不跑 `ntp_worker`，由 `init_clock_pcf` 从 PCF 恢复时钟。

## 6. 电池管理

### 6.1 ADC 电压检测

电池通过分压电路接到 ADC 引脚（板级定义：v2=GPIO2，v1=GPIO4）：

```rust
// src/main.rs:204-208
let bat_adc1_pin = adc1_config
    .enable_pin_with_cal::<_, AdcCalCurve<esp_hal::peripherals::ADC1>>(
        crate::board::bat_pin(),
        Attenuation::_11dB,
    );
```

ADC 使用曲线校准（`AdcCalCurve`）提高精度，11dB 衰减允许测量接近电源电压的信号。

### 6.2 电池百分比

```rust
// src/battery.rs:37-64（简化）
const V_MAX: u32 = 4100;   // mV
const V_MIN: u32 = 3100;

let voltage_mv = adc_value as f32 * 2.0;    // 分压比 1:2
let percent = if voltage_mv > V_MAX as f32 {
    100
} else if voltage_mv < V_MIN as f32 {
    0
} else {
    // 平方曲线：拟合锂电池放电平台（中段电压变化平缓）
    let normalized = (voltage_mv - V_MIN as f32) / (V_MAX - V_MIN) as f32;
    (normalized * normalized * 100.0).round() as u32
};
v.percent = percent.clamp(0, 100);
unsafe { *core::ptr::addr_of_mut!(LAST_BATTERY_PERCENT) = v.percent; }
```

电量百分比存入 RTC 内存，渲染路径可以通过 `battery::last_percent()` 同步读取（无需 await）。低于 20% 时打印低电量警告。由于电子墨水屏刷新慢，电量信息不需要实时更新。

### 6.3 周期采样

```rust
// src/battery.rs:94（采样任务循环尾部）
Timer::after_secs(60).await;  // 每 60 秒采样一次
```

60 秒的采样周期平衡了实时性和功耗。ADC 偶发读数错误会重试（上限 50 次），持续失败则保留上次电量。

## 7. 功耗分析

各状态的估算功耗：

| 状态 | 功耗 | 持续时间 |
|------|------|---------|
| WiFi 开启 + 渲染 | ~100mA | 每次几秒 |
| 渲染（无 WiFi） | ~30mA | 每次几百毫秒 |
| 待机（CPU 运行，屏灭） | ~10mA | 短暂 |
| 深度睡眠（PCF 计时） | ~10μA | 绝大部分时间 |

以 1000mAh 锂电池为例：
- 天气刷新每 5 小时一次（WiFi 开启约 5 秒）：100mA × 5s / 18000s ≈ 0.028mA 平均
- 分钟级定时唤醒（时间显示开）：每次唤醒几秒渲染 + 联网刷新，平均电流仍远低于 0.1mA
- 用户交互（按键、翻页）按每天 30 分钟计：30mA × 0.5h / 24h ≈ 0.625mA 平均
- 深度睡眠 99%+ 的时间：10μA ≈ 可忽略
- **预估续航：数周到数月**（取决于使用频率）

几个设计让"醒着的时间"尽可能短：定时唤醒立即回睡（1.5）砍掉了刷新后的空闲等待；股票页非开盘直接睡到下一开盘，不空转；定时唤醒首帧保持快刷，省时间也省电。如果只是偶尔阅读电子书（不频繁联网），续航可以达到数周甚至更长。

## 小结

| 技术点 | 要点 |
|--------|------|
| 深度睡眠 | `sleep_deep()` + RTC 保持供电 |
| 睡眠布防 | PCF8563 分档：秒档/分档/绝对报警，失败退 ESP RTC 定时 |
| 唤醒源 | GPIO RTC 唤醒（按键梯）+ PCF INT（→GPIO4）+ 定时器兜底 |
| 立即回睡 | 定时唤醒刷新完成即睡，用户碰键回退空闲流程 |
| 唤醒分类 | `consume_timer_wake` 读 TF/AF；非定时唤醒首帧强制全刷 |
| 模式切换 | `reboot_sleep` 50ms 短深睡，保留 rtc_fast，不用 software_reset |
| RTC 内存 | `#[ram(unstable(rtc_fast))]`，深睡保持；IO 唤醒会丢 → NVS 哨兵兜底 |
| 电源轨 | v1 双轨 / v2 单轨，睡前统一断电（防唤醒瞬间拉塌电池轨） |
| 深睡引脚 | GPIO2 隔离（slp_sel + 关 IE/WPU/WPD）；pad hold 按板处理 |
| WiFi 省电 | 30 秒无请求自动关闭，需要时重连 |
| 电池 | ADC 采样 + 曲线校准，60 秒周期，平方曲线拟合放电平台 |
| 电子墨水屏 | 断电不丢失，睡眠前渲染待机画面 |

低功耗设计的核心思路：**让 CPU 和外设尽可能多地在深度睡眠中度过，只在必要时短暂醒来工作**。电子墨水屏的"断电不丢失"特性与深度睡眠完美配合——睡眠前渲染的画面就是设备的"外观"。
