# 第 10 篇：电子书阅读 —— 矢量字体 / 点阵字体 / 动态分页

> English: [en/10-ebook-reading-and-vector-fonts.md](en/10-ebook-reading-and-vector-fonts.md)

> 用 Rust 构建ESP32-C3 电子墨水屏阅读器 · 系列文章

电子书阅读是这台设备的核心功能。它要在 400×300 的电子墨水屏上把 TXT 小说排得好看、翻得流畅，还要支持任意字号、行距/笔画微调、书签、跳转、续读、字体选择、横竖屏旋转、方向键互换、书单二级目录——全部在 400KB SRAM、无 FPU 的 ESP32-C3 上完成。本篇把阅读子系统从底层字形渲染到上层导航完整讲清楚。

## 为什么阅读要单独拿出来说

阅读子系统有几个独有的难题，别处碰不到：

1. **字号任意 + 中文**：菜单能用固定点阵字库，但阅读要让用户调字号，固定字库做不到——必须有**矢量字体**（TTF），按字号实时栅格化。
2. **内存压力**：TTF 解析需要大缓冲（点坐标、字形轮廓、字形位图缓存），ESP32-C3 只有 400KB SRAM，而正常模式 WiFi 协议栈本身就吃掉一大块。
3. **软浮点光栅化慢**：C3 没有 FPU，TTF 的二次贝塞尔曲线展开 + 像素覆盖率计算是重活，一页上百字要精心优化才不卡。
4. **分页与双向翻页**：电子墨水屏刷新慢，翻页体验取决于分页算法——既不能预建全书索引卡住进书，又要支持向前/向后任意翻。

本项目的解法是：**阅读与正常模式分启动**（互不抢内存）+ **TTF 与点阵双字体模式** + **字节偏移动态分页**。下面逐一展开。

## 1. 阅读模式：独立重启，独占堆

### 为什么要分模式

正常模式（天气/股票/日历/配网）需要 WiFi，embassy-net + TLS 协议栈会吃掉约 60KB 堆。而阅读模式需要 TTF 大缓存 + 深调用栈。两者**运行期堆互斥**——同时开就会 OOM。

如果把 TTF 缓冲放进 `.bss` 常驻，正常模式就永远少了这块；如果用 `Box` 在阅读时分配，正常模式的 WiFi 堆又不够。最干净的办法是**按模式分启动**：进阅读就重启，不初始化 WiFi，整块堆给 TTF；离开阅读再重启回正常模式。

### 重启分模式的实现

关键是用 **`reboot_sleep()`**（50ms 深睡 + RTCIO/定时器唤醒），而不是 `software_reset()`：

```rust
// src/sleep.rs
pub async fn reboot_sleep() {
    // ... 等渲染空闲、关 EINK/SD 电源 ...
    RTC_MANGE.lock().await.as_mut().unwrap().sleep_deep(ws.as_slice());
}
```

深睡唤醒会重跑 `main`，重新分配堆、重新决定起不起 WiFi，而 **`rtc_fast` 内存跨深睡保留**（但**不跨 `software_reset`**）。所以跨重启的标志放在 `rtc_fast`：

```rust
// src/pages/read/page.rs
#[ram(unstable(rtc_fast))]
pub(crate) static mut PAGE_INDEX: Option<u32> = None;   // 选中的书索引
#[ram(unstable(rtc_fast))]
pub(crate) static mut READING_MODE: bool = false;        // 本次启动是否进阅读
#[ram(unstable(rtc_fast))]
static mut TTF_RESUME_OFFSET: u32 = 0;                   // 跨复位续读偏移
#[ram(unstable(rtc_fast))]
static mut RESUME_SUBDIR: [u8; BOOK_NAME_MAX] = ...;     // 续读的书所在子目录
#[ram(unstable(rtc_fast))]
static mut LIST_SUBDIR: [u8; BOOK_NAME_MAX] = ...;       // 书单层记忆：上次所在子目录
#[ram(unstable(rtc_fast))]
static mut LIST_BOOK_IDX: u32 = 0;                       // 书单层记忆：上次选中的书下标
```

### 启动分流（src/main.rs）

`main` 开头判断 `READING_MODE`：是则 spawn `reading_task`、跳过 WiFi；否则走正常模式连 WiFi。RTCIO 唤醒会丢 `rtc_fast`，所以阅读标志还有一层 **NVS 兜底**（`SleepPageStorage` 的哨兵值 100，见第 4 节）：

```rust
// v22：IO（RTCIO）唤醒会丢 rtc_fast 的 READING_MODE——从 NVS 恢复"上次在阅读"
if crate::storage::read_sleep_page() == Some(SleepPageStorage::PAGE_READING) {
    core::ptr::addr_of_mut!(crate::pages::read::READING_MODE).write(true);
}
let reading_mode = unsafe { *core::ptr::addr_of!(crate::pages::read::READING_MODE) };
if reading_mode {
    crate::worldtime::init_clock_pcf().await;   // 无 WiFi，用 PCF8563 恢复时钟
    spawner.spawn(crate::battery::test_bat_adc().unwrap());
    spawner.spawn(crate::pages::reading_task(spawner.clone()).unwrap());
    // main 不返回，交互由 reading_task 处理
    loop { Timer::after(Duration::from_secs(5)).await; }
}
```

### 进入 / 退出阅读

- **进入**：主网格菜单选"电子书"→ `EReadPage` 分支设 `READING_MODE=true`、`PAGE_INDEX=None`、NVS 写 `PAGE_READING` 哨兵 → `reboot_sleep()` → 唤醒后 `main` 进阅读书单。在书单里选书时设 `PAGE_INDEX=Some(book)`，同时把书所在子目录记进 `RESUME_SUBDIR`。
- **退出**：`ReadPage` 的 `run()` 返回（`running=false`）→ `reading_task` 清 `READING_MODE=false`、主网格页 `PAGE_INDEX=-1`、NVS 写 -1 → `reboot_sleep()` → 唤醒回正常模式。

```rust
// src/pages/mod.rs
#[embassy_executor::task]
pub async fn reading_task(spawner: Spawner) {
    // 等显示任务就绪（reading_task 比 EPD init 快，不等会首帧空白、不旋转）
    let mut waited = 0u32;
    while crate::display::display_mut().is_none() {
        if waited > 150 { break; }  // 最多等 ~3s（防御；正常 ~百 ms 就绪）
        waited += 1;
        Timer::after(Duration::from_millis(20)).await;
    }
    let mut p = read::ReadPage::new();
    p.bind_event().await;
    p.run(spawner).await;
    // 离开阅读：清标志 → reboot_sleep 回正常模式
    unsafe {
        core::ptr::addr_of_mut!(read::READING_MODE).write(false);
        core::ptr::addr_of_mut!(main_page::PAGE_INDEX).write(-1);
    }
    crate::storage::write_sleep_page(-1);
    crate::sleep::reboot_sleep().await;
}
```

### 堆的归宿

堆放在独立的 **`dram2` 段**（bootloader 释放的 ~64KB DRAM，原本空闲），不占主 DRAM：

```rust
// src/main.rs
#[link_section = ".dram2_uninit"]
static mut DRAM2_HEAP: MaybeUninit<[u8; 65280]> = MaybeUninit::uninit();
// esp_alloc::HEAP.add_region(HeapRegion::new(ptr, 65280, Internal.into()));
```

主 DRAM 全部留给栈（TTF 渲染异步链很深，曾经 64KB 堆放主 DRAM 时栈溢出）。阅读与正常模式共用这一块堆，无需按模式区分。

## 2. 两种字体模式

阅读支持两种字体，用户在"字体"菜单里切换：

| | TTF 矢量字体 | 点阵字体 |
|---|---|---|
| 来源 | SD 卡 `fonts/*.ttf`（无此目录则仅点阵） | 固件内置 u8g2 wqy 位图 |
| 字号 | 任意（用户可调 12–40px） | 固定（12/14/16 三档） |
| 宽度 | 按 `advance` 比例宽度 | 固定单元格（中文满宽/英文半宽） |
| 渲染 | 软浮点光栅化（慢，~10ms/字冷缓存） | 直接 blit 位图（极快） |
| 字库 | TTF 内全部字形（simhei 等） | GB2312 子集（~7700 字） |
| 分页 | 逐字 `advance` 量宽换行 | 纯算术 |

### 2.1 TTF 矢量字体（src/ttf_sd.rs）

TTF 渲染**没有用第三方解析库**，而是自己实现了一套按需解析器。原因是嵌入式下要把所有缓冲打包进一个可控的工作区，并尽量复用、少读 SD。

**解析流程**（首次 `open_font` 时读表目录，结果缓存在 `TtfWs.fi`）：

```
表目录 → head(units_per_em/loc_fmt) / hhea(ascent/descent/num_h_metrics)
       → maxp(num_glyphs) / cmap(字符→字形映射) / loca(字形偏移表) / glyf(字形数据) / hmtx(水平度量)
```

为了翻页不每字读 SD，**cmap/hmtx/loca 整表缓存进 RAM**（`TtfWs` 里的 `cmap_cache`/`hmtx_cache`/`loca_cache`，容量上限 28KB/1KB/1KB），只有 `glyf`（字形轮廓，最大）是逐字形从 SD 随机 `seek+read`：

```rust
// 每个字形：char_to_gid(cmap) → loca 取偏移 → 读 glyf → 解析轮廓 → 栅格化
let gid = char_to_gid(font_f, ws, fi, ch);   // cmap 命中 RAM 缓存，否则 SD 回退
let adv = advance(font_f, ws, fi, gid);       // hmtx 命中 RAM 缓存
let (pts, contours, bbox) = parse_glyph(font_f, fi, gid, ws);  // 读 glyf
let bmp = rasterize_to_bitmap(...);           // 光栅化
```

cmap 子表优先选格式 12（score 高），否则格式 4；装得进 28KB 缓存就从 RAM 查，装不下走 `char_to_gid_sd` 从 SD 随机读（慢，但能跑）。cmap 缓存从早期的 2KB 放宽到 **28KB**——正好容下子集字体的整个 cmap 子表（如 Light_gb2312 的 fmt4 ~28KB）；simhei 证明：只要 cmap 进缓存，loca/glyf 走 SD 回退也足够快（cmap 是每字都要查的瓶颈）。换字体时 `parse_font_info` 无条件清零三张表缓存长度，避免"新字体 + 旧缓存"错配（表现为所有字符变问号）。

**光栅化**用 `ab_glyph_rasterizer`（覆盖率栅格化器，配 `libm` 提供 no_std 软浮点）。它把二次曲线展开成边，再扫描线计算每个像素的覆盖率。像素置位判定是 **`覆盖率 × stroke_weight ≥ 0.35`**（低于 0.5 的基础阈值，让细笔画不断裂）：系数默认 ×1.0，排版菜单"笔画"项可调 ×1.0~×3.0（步进 0.1，存 `StrokeConfigStorage`）。乘法对低覆盖度的细横线提升显著（断墨修复立竿见影），大片墨区早已饱和不受影响，边缘只轻微增宽。

**字形缓存**：栅格化太贵，所以缓存。位图区是 **12KB 扁平缓冲**，运行时按字号自适应切槽位：每槽 `((px+2)+7)/8 × (px+2)` 字节（CJK 字形约 px×px，1-bit 打包），槽数 = 12288/槽字节（上限 256）。字号大 → 槽大、槽少（够用）；字号小 → 槽小、槽多。环形覆盖式（满则覆盖最旧）。一页去重后约上百字形，这套缓存基本能让"渲染当前页 → 预加载下一页"两次都命中缓存，翻页时直接 blit。字形位图超过槽容量（>256B）时走直绘回退：不缓存、光栅化后逐像素画屏。

**`TtfWs` 工作区**约 53KB，堆分配（`alloc_ws`/`free_ws`，直接 `Layout` 分配避免 `Box::new` 的栈临时量），进阅读创建、退出释放：

```rust
pub struct TtfWs {
    pub pts_x: [i32; 600], pub pts_y: [i32; 600], pub pts_on: [u8; 600], // 字形点
    pub end_pts: [u16; 96],                                              // 轮廓端点
    pub cmap_cache: [u8; 28672], pub hmtx_cache: [u8; 1024], pub loca_cache: [u8; 1024],
    pub glyf_buf: [u8; 2048], pub book_buf: [u8; 2048],                  // glyf / 正文缓冲
    pub gc_gid: [u16; 256], pub gc_w: [u8; 256], pub gc_h: [u8; 256],
    pub gc_yoff: [i16; 256],                                             // 字形缓存元数据
    pub gc_bmp: [u8; 12288],                                             // 12KB 扁平位图区
    pub gc_slot_bytes: usize, pub gc_n_slots: usize, pub gc_next: usize, // 槽位/游标
    pub fi: Option<FontInfo>,                                            // 解析后的度量
}
```

### 2.2 点阵字体（src/pages/read/bitmap.rs）

点阵模式用**固件已链接的 u8g2 wqy 位图字体**（菜单/日历一直在用），无需 SD 字库、无需光栅化，渲染是直接 blit 闪存里的位图——比 TTF 快得多。这是为追求翻页速度的场景准备的。

宽度模型是**固定单元格**：中文 `full_w`、英文/数字 `half_w`（中文惯例半宽），不查字形实际宽度。于是分页是纯算术（数行数/单元格），渲染是逐字 blit 到单元格起点：

```rust
// 渲染：逐字画到单元格，pen_x 按宽度推进
let w = if (ch as u32) < 0x80 { half_w } else { full_w };
if pen_x + w > max_w { 换行 }
font.render_aligned(&ch_str, Point::new(pen_x, pen_y), ...);
pen_x += w;
```

三个函数与 TTF 一一对应：`paginate_render_bitmap` / `compute_consumed_bitmap` / `find_prev_start_bitmap`。

**字体精简**：系统里只保留 wqy **12/14/16** 三种（删掉了 wqy15、wqy12b/wqy14b 粗体变体），净省约 463KB flash。每套 wqy（GB2312 全字库）约 12号 198KB / 14号 242KB / 16号 301KB。

### 2.3 字体选择

字体菜单列出可用字体：扫描 SD 卡 **`fonts/`** 目录（长文件名 LFN + 8.3 短名回退；`books/` 只放书），末尾固定追加内置的"点阵16/点阵14/点阵12"。列表容量 16，预留末尾 3 个点阵位——TTF 最多收 13 个，避免 TTF 占满把点阵挤掉（push 静默失败）。

```rust
fn bm_size_of(name: &str) -> Option<u32> {
    match name { "点阵16" => Some(16), "点阵14" => Some(14), "点阵12" => Some(12), _ => None }
}
fn is_bitmap(name: &str) -> bool { bm_size_of(name).is_some() }
```

选中点阵时**不打开 .ttf 文件**（`font_file_ptr=null`），但**仍分配 `TtfWs`**——复用它的 `book_buf`（2KB）来读正文，这样阅读基础设施（读 `.txt`、历史栈、续读）两条路径共用。`bm_size_of(字体名)` 在渲染/分页处分流走点阵还是 TTF。换字体 = 重开句柄 + `cache_clear` 清字形缓存 + `ws.fi=None` 清字体表缓存 + 清历史栈（页边界全变了）。

## 3. 动态分页与导航

### 3.1 不预建全书索引

电子墨水屏阅读器常见的做法是进书时扫一遍全书建页索引，翻页查表 O(1)。但本项目**不这么做**——因为进书时扫全书（TTF 要逐字量宽）会卡住几秒甚至几十秒，体验很差。

取而代之是**字节偏移动态分页**：每个页面记录它在 `.txt` 里的**起始字节偏移**和**结束字节偏移**（渲染返回的"本页消费了多少字节"）。给定偏移即可即时渲染一页，不需要全局索引。

### 3.2 前进 / 后退

- **前进 O(1)**：`ttf_offset ← ttf_end`。当前页消费完的偏移就是下一页起点，永远精确。
- **后退 O(1)**：历史栈 `ttf_hist`（256 槽）。前进时把当前页起点压栈（栈满丢最老记录，保持"最近 256 页"语义——否则满后 push 静默失败，后退会弹到会话早期读过的老位置），后退时弹栈，与前进完全对称、精确。
- **后退栈空时**（刚进入/跳转后第一次后退）：历史栈没东西可弹，调 `find_prev_start` 现算上一页起点。

```rust
// src/pages/read/page.rs
async fn do_change_page(&mut self, next: bool) {
    if next {
        if self.ttf_at_end { /* 末页提示一次，不前进 */ return; }
        if self.ttf_hist.is_full() { self.ttf_hist.remove(0); }
        let _ = self.ttf_hist.push(self.ttf_offset);
        self.ttf_offset = self.ttf_end;
    } else {
        if let Some(prev) = self.ttf_hist.pop() {
            if prev >= self.ttf_offset { return; }  // 已到开头
            self.ttf_offset = prev;
        } else {
            let prev = self.find_prev_page_start();  // 栈空：现算上一页
            if prev >= self.ttf_offset { return; }
            self.ttf_offset = prev;
        }
    }
    self.ttf_end = self.ttf_offset;
    // 存 rtc_fast + 触发渲染 + 持久化位置
}
```

正常阅读（前进再后退）几乎都走历史栈，只有"刚打开书就往后翻"或"跳转后往后翻"这种罕见情况才现算。

### 3.3 find_prev_start：现算上一页起点（难点）

这是整个阅读子系统最难的部分。核心性质：**真页边界 `pk-1` 满足 `pk-1 + 一页消费字节数 ≤ cur_start` 且最接近**（上一页正好在当前页起点处或之前结束）。

朴素做法是从 offset 0 逐页扫到 `cur_start`，返回最后一个边界——准确（每一步都是真边界、字符对齐），但 TTF 大字体下逐字量宽太慢。本项目的做法是**二分定位 + 字符对齐 + `≤` 判定**：

```rust
// src/ttf_sd.rs (TTF) / src/pages/read/bitmap.rs (点阵) 同结构
pub fn find_prev_start(..., cur_start, ...) -> u32 {
    // ① 二分（仅在字符对齐点测试）：找最大 X 使 X+consumed(X) ≤ cur_start
    let mut lo = 0; let mut hi = cur_start;
    while lo + 16 < hi {
        let mid = align_down_char(book_f, (lo + hi) / 2);  // 字符对齐
        if mid <= lo { break; }
        let c = consumed_at(mid);
        if c > 0 && mid + c <= cur_start { lo = mid; } else { hi = mid; }
    }
    // ② 精化：从 hi 向下找首个字符对齐 P-true = pk-1（最多 32 步）
    let mut x = align_down_char(book_f, hi);
    let mut steps = 0;
    while steps < 32 {
        let c = consumed_at(x);
        if c > 0 && x + c <= cur_start { return x; }
        if x == 0 { break; }
        x = align_down_char(book_f, x - 1);
        steps += 1;
    }
    lo  // 兜底：lo 是字符对齐 P-true（二分保证），绝不返回 0-失败
}
```

这里三个细节是用真金白银的 bug 换来的教训：

1. **二分而非全扫**：只扫几十页（不是全书），TTF 中小字体几百毫秒可接受。
2. **字符对齐（`align_down_char`）**：测试只在 UTF-8 字符起点进行。否则半字符起点会让 `compute_consumed` 把续字节当成满宽的 `FFFD`（1 字节却占满宽）扭曲页大小，导致落到非字符边界——那一页首字就显示成"块"（半字符乱码）。
3. **判据用 `≤` 而非 `==`**：`consumed(pk-1)` 偶尔和 `cur_start - pk-1` 差 ±1 字节（TTF advance 浮点取整、缓冲边界等），用 `==` 命中不到就会返回 0 → **跳回第一页**；用 `≤` 必有解（`lo` 兜底），永不跳页。

### 3.4 跳转与书签

- **跳转 = 百分比**：菜单输入 0–100%（短按 ±1、长按连发加速：步进 1→5→10→50→100→200→400，带进度条预览），确认后 `off = input_pct × file_len / 100`，`jump_to_offset` 清空历史栈（大跳转后历史失效）、设偏移、写 `TTF_RESUME_OFFSET`、触发渲染。
- **书签 = 字节偏移**：`.log` 文件存 `Vec<u32>`，`[0]` 是最后位置（**低 31 位 = 偏移，bit31 = 已到末页标记**）、`[1..]` 是书签。书签界面是"列表 + 操作弹层"两级：
  - **列表**：行 0 = 收藏书签（确认即把当前进度入列，去重、上限 100），行 1..n = 已有书签（每项显示 `X.XXX%`），行 n+1 = 取消；下方 1/3 高度的预览框跟随选中项。
  - **操作弹层**：选中某个书签确认后弹出，两行"打开（默认）/ 删除"，再确认才执行——收藏、打开、删除合并进了一个入口。
  - **预览**：从 `.txt` 书签偏移处读 512B，截到 UTF-8 字符边界再渲染（512%3=2，中文几乎必然截在多字节字符中间；`from_utf8` 全有或全无，不截边界整段失败 → 预览空白）。绘制时**不用 `display.clipped()` 视图**——旋转屏下 `DrawTarget` 的 bounding_box 是物理尺寸（高 300），clip 会在 y=300 被静默截断，预览只能显示前两行（历史 bug）；改为手动折行 + 逐行 `render_aligned` 直接画到 display，行数按预览区底边越界 break。
- **末页**：渲染时若 `offset + consumed ≥ file_len` 置 `ttf_at_end`；真末页能正常显示，到尾再按前进才叠一次"已是最后一页"提示。bit31 标记随翻页写进 `.log[0]`，书单据此直接显示 100.000%。

### 3.5 书单：二级目录与进度列

书单不再只有一层：`books/` 下的**子目录可进入**，目录项排在书前面（二级目录里首项是 `..` 返回上级；只有两级，子目录内不再嵌套）。

- **进入**走 `change_dir` 原位换目录（LFN 目录名经 `find_entry_by_name` 拿盘上 SFN 别名）；**返回上级**经 SD 根重开 `books/` 并 replace+close 旧句柄（释放 VolumeManager 的目录槽位）。换层后重扫子目录/书列表/进度，光标归零。
- **层与光标跨深睡记忆**：续读的书所在子目录存 `RESUME_SUBDIR`；普通进入书单时按 `LIST_SUBDIR` + `LIST_BOOK_IDX`（最后打开的书所在子目录与书下标）恢复目录并选中——都是 rtc_fast，断电归零。
- **每本书右侧显示阅读进度** `X.XXX%`（偏移 ×100_000 / 文件长度，u64 中间量防溢出；bit31 置位 → `100.000%`）。长书名按 wqy16 实测渲染宽度截断补 `…`，不与进度列重叠。

### 3.6 方向键与"方向键互换"

方向键（Key1/Key2）的短按/长按统一走 `dir_key_short`/`dir_key_long`（`down` 参数 = "向下/+1/下一页"语义）。菜单项"方向键互换"切换 `swap_keys`，`bind_event` 据此把两条物理键的 `down` 取值对调——开启后**阅读功能内**（翻页/菜单/跳转/排版/字体/书签/书单）方向整体互换，并写入 flash（`ReadingFlagsStorage`，magic `PGSW`）持久化，重启保留。

## 4. 续读：跨重启回到上次位置

续读有多套互补的存储，应对不同场景：

| 存储 | 位置 | 跨重启 | 用途 |
|---|---|---|---|
| `TTF_RESUME_OFFSET` | rtc_fast RAM | 跨 `reboot_sleep` 深睡 | 唤醒即恢复（快） |
| `RESUME_SUBDIR` / `LIST_SUBDIR` / `LIST_BOOK_IDX` | rtc_fast RAM | 跨 `reboot_sleep` 深睡 | 续读/书单的目录与光标 |
| `.log[0]` | SD 卡文件 | 跨任意重启 | 权威持久化 + 书单进度 |
| `SleepPageStorage`（哨兵 100） | NVS flash | 跨任意重启 | RTCIO 唤醒丢 rtc_fast 时恢复"上次在阅读" |

**进入流程**：

1. `ReadPage::new` 读 `PAGE_INDEX`（选中的书）和 `TTF_RESUME_OFFSET`，设 `ttf_resume=true`；同时恢复 `RESUME_SUBDIR`（续读）或 `LIST_SUBDIR/LIST_BOOK_IDX`（书单层）。
2. `get_page_vec` 打开 `.txt` 取文件长度；`ttf_resume=true` 时保留预置偏移（夹到 file_len）。
3. `get_log_vec` 读 `.log`；`ttf_resume=true` 时跳过 `.log[0]` 覆盖（rtc_fast 权威），否则用 `.log[0]` 的低 31 位还原。**最后把还原后的偏移同步回 `TTF_RESUME_OFFSET`**——这一步修了一个坑：打开书时 `TTF_RESUME_OFFSET` 被清 0、由 `.log[0]` 还原了屏幕偏移但没同步回 rtc_fast，导致"未翻页直接睡眠唤醒会回第一页"。

**注意**：rtc_fast **不跨 `software_reset()`**（CoreSw 复位会清 rtc_fast），所以模式切换一律用 `reboot_sleep()`（深睡），不能用 `software_reset`；RTCIO 唤醒（按键唤醒设备）同样会丢 rtc_fast，才需要 NVS 哨兵兜底。

### 排版与按键偏好持久化（storage.rs）

字号、行距、旋转、字体名、笔画系数、方向键互换全部落 flash，进书时恢复：

```rust
// src/storage.rs
pub struct ReadingSettings {
    pub ttf_px: u8,        // 字号 12–40
    pub line_gap: i8,      // 行距 -10..+10（负值收紧行间）
    pub rotate: u8,        // 旋转 0–3
    pub font_name: [u8; 32], // null 结尾字体名（.ttf 或 点阵XX）
}
// 追加在存储链末尾的两个独立小结构：
pub struct ReadingFlagsStorage { pub magic: u32, pub swap_keys: u8 } // magic "PGSW"
pub struct StrokeConfigStorage { pub magic: u32, pub weight_x10: u8 } // magic "STKE"，10..=30
```

`font_name` 校验放宽：接受 `.ttf` 或内置点阵名（`is_ttf || is_bitmap`），非法回退 `font.ttf`，防止 flash 未初始化区域的垃圾字节被当成字体名导致打开失败；读取时各值都 clamp 到合法区间。新结构一律**追加在存储链末尾**，不动既有字段——那会挪动后续偏移、丢用户数据。

## 5. 屏幕适配与旋转

三套 layout 模块按屏幕特性编译期选择（feature gate）：

| 模块 | 屏幕 | 原生分辨率 | 默认旋转 |
|---|---|---|---|
| `layout_400x300` | 4.2 寸 | 400×300 | Rotate90 |
| `layout_176x264` | 2.7 寸 | 176×264 | Rotate0 |
| `layout_128x296` | 2.9 寸 | 296×128 | Rotate90 |

每个模块提供旋转感知的几何函数：

```rust
pub fn visual_width() -> u32 { if swapped() { DISPLAY_HEIGHT } else { DISPLAY_WIDTH } }
pub fn visual_height() -> u32 { if swapped() { DISPLAY_WIDTH } else { DISPLAY_HEIGHT } }
pub fn text_width() -> u32 { visual_width() }       // 文本区满宽（顶到屏左边）
pub fn text_left_margin() -> i32 { 0 }
pub const PROGRESS_AREA_HEIGHT: u32 = 8;             // 底部进度条预留（条仅 3px）
```

**4 向旋转**：`ROTATE_STATE` 是 `AtomicU8`，菜单"旋转屏幕"依次 +90°（菜单保持打开便于连续旋转）。`PROGRESS_AREA_HEIGHT` 从早期的 20 降到 8（进度条实际只有 3px 高，旧值浪费了近一行的文本区高度）。

**菜单自适应**：阅读菜单（9 项）的高度按 `visual_height` 动态算行高（可用高度均分后 clamp 到 12–24px），小屏（vh<200，如 2.7 寸横屏 176 高）放不下 9×24 的固定菜单，改用更小行高 + wqy12 字号；大屏维持 wqy14。书签列表同样有紧凑模式（预览占一半高、行高 12/14）。

**行数计算**：`max_lines = (文本区高 − 一份墨迹高) / (行高 + 行距) + 1`——预算先扣掉末行的一份完整墨迹（负行距只压缩行间空隙、不压缩墨迹），余量按"行槽"均分；`line_h = 文本区高 / max_lines` 再均分余量，让文本铺满整屏。正文区高度 = `visual_height − PROGRESS_AREA_HEIGHT − 12`（状态行电量图标 9px + 进度条带）。**负行距**整体上移：`shift = min(line_gap, 0)`，首行起点 y = 2+shift、预算高度等量加回（`text_area_h − shift`），末行墨迹约束不变——行间压缩且首行顶距同步收紧。正文渲染、反向分页、预加载三处必须用同一公式，保证行数一致。

## 8. 性能与权衡小结

- **TTF vs 点阵**：TTF 字号任意、字形丰富，但光栅化慢；点阵极快但字库有限（GB2312）、字号固定。给用户两种选择，追求速度用点阵。
- **预加载按时间出让 CPU**：渲染完当前页后 `preload_glyphs` 预光栅化下一页字形（只缓存不画）。软浮点光栅化是重活（单字随字号平方涨：16px ~4ms、40px ~40ms，一页上百字），所以预加载每 **≥10ms** 就 `Timer::after(1µs)` 让出一次——按时间而非按字数，否则大字号下出让间隔会拉到几百 ms，表现为翻页后按键长时间无响应。出让后显示任务并行刷屏，屏幕先出图、预加载在后台跑完。
- **后退 `find_prev_start`**：二分 + 字符对齐 + `≤`，只扫几十页。点阵纯算术很快；TTF 中小字体可接受；TTF 大字体较慢——这种场景建议用点阵模式阅读。
- **不预建全书索引**：换来进书零延迟，代价是后退栈空时要现算（但绝大多数后退走历史栈 O(1)）。
- **字体精简**：系统只留 wqy 12/14/16，省 ~463KB flash。

阅读子系统是这台设备工程量最大的部分，也是踩坑最多的——从最初的静态分页、到全书页索引、再到字节偏移动态分页 + 历史栈 + `find_prev_start`，分页模型迭代了多轮。最终这套方案在"进书零延迟、前进瞬时、后退绝大多数瞬时、内容准确"之间取得了平衡。
