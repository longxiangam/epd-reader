## 引言

在 296×128 或 400×300 像素的电子墨水屏上设计 UI，是一种独特的体验。没有色彩、没有动画、刷新慢——但你可以用像素精确控制每一个元素的位置。本项目的 UI 系统基于 `embedded-graphics` 框架，通过组件化和页面路由实现了清晰的应用结构。

## 1. embedded-graphics 与 Drawable trait

`embedded-graphics` 是 Rust 嵌入式图形的基石。它的核心是 `Drawable` trait：

```rust
// embedded-graphics 定义的 trait
pub trait Drawable {
    type Color: PixelColor;
    type Output;
    fn draw<D: DrawTarget<Color = Self::Color>>(
        &self,
        target: &mut D,
    ) -> Result<Self::Output, D::Error>;
}
```

任何实现了 `Drawable` 的类型都可以绘制到任意 `DrawTarget` 上——屏幕、帧缓冲区、甚至另一个组合组件。这种解耦让组件完全不知道自己最终绘制到哪里。

本项目所有的 UI 组件都实现了 `Drawable`：

```rust
// src/widgets/icon_grid_widget.rs:132-148
impl<C> Drawable for IconGridWidget<C>
where C: PixelColor + Clone
{
    type Color = C;
    type Output = ();

    fn draw<D>(&self, target: &mut D) -> Result<Self::Output, D::Error>
    where D: DrawTarget<Color = Self::Color>
    {
        for cell in self.cells.iter() {
            let _ = cell.draw(target);  // 每个格子也是 Drawable
        }
        Ok(())
    }
}
```

## 3. 温度趋势图（TempChart）

天气页面中的温度曲线是一个典型的数据可视化组件：

```rust
// src/widgets/temp_chart.rs:23-108（简化）
pub fn draw_temp_chart<C, D>(
    position: Point,
    chart_size: Size,
    points: &[TempPoint],    // 各天温度数据
    color: C,
    target: &mut D,
) -> Result<(), D::Error>
{
    // 1. 计算温度范围
    let temp_min = ... - 2;  // 留余量
    let temp_max = ... + 2;

    // 2. Y 坐标映射函数
    let temp_to_y = |temp: i32| -> i32 {
        chart_y + chart_h - ((temp - temp_min) * chart_h / temp_range)
    };

    // 3. 水平参考线（每 5°C 一条）
    let mut t = (temp_min / 5) * 5 + 5;
    while t < temp_max {
        Line::new(...).into_styled(stroke).draw(target)?;
        t += 5;
    }

    // 4. 高温折线 + 低温折线
    draw_polyline(&high_pts, thick_stroke, dot_fill, target)?;
    draw_polyline(&low_pts, thick_stroke, dot_fill, target)?;
}
```

## 5. Page Trait 与页面路由

### 5.1 Page Trait

所有页面都实现统一的 `Page` trait：

```rust
// src/pages/mod.rs:57-77
pub trait Page {
    fn new() -> Self;
    async fn render(&mut self);      // 渲染页面内容
    async fn run(&mut self, spawner: Spawner);  // 运行页面逻辑
    async fn bind_event(&mut self);  // 绑定事件监听

    // 裸指针辅助：事件回调需要 &mut 页面，而回调是 'static 的——
    // 绑定时把页面地址存进监听器，回调里再转回来
    fn mut_by_ptr<'a, T>(ptr: Option<usize>) -> Option<&'a mut T> { ... }
    fn mut_to_ptr<T>(ref_mut: &mut T) -> usize { ... }
}
```

事件绑定用 `on_target(event, ptr, callback)` 把页面地址一起注册（见 5.3），回调内通过 `mut_by_ptr` 还原 `&mut Self`——这是 no_std 环境下"回调持有页面状态"的惯用法，代价是页面被 move/回收后指针悬垂，所以退出页面必须 `clear()`。

### 5.2 页面路由

`MainPage` 是页面路由器，它维护菜单列表和当前选中的页面：

```rust
// src/pages/main_page.rs:272-355（简化）
async fn run(&mut self, spawner: Spawner) {
    loop {
        if None == self.current_page {
            self.render().await;  // 渲染主菜单（IconGridWidget，3 列 7 项）
            continue;
        }
        let menu_item = &self.menus[self.current_page.unwrap()];
        match menu_item.page_enum {
            EReadPage => {
                // 重启分模式：置 rtc_fast 阅读标志 + NVS 哨兵
                // → 50ms 短深睡唤醒后 main 直接进阅读模式（见第 7 篇 1.7）
                unsafe {
                    core::ptr::addr_of_mut!(crate::pages::read::READING_MODE).write(true);
                    core::ptr::addr_of_mut!(crate::pages::read::PAGE_INDEX).write(None);
                }
                crate::storage::write_sleep_page(
                    crate::storage::SleepPageStorage::PAGE_READING,
                );
                crate::sleep::reboot_sleep().await;
            }
            EWeatherPage => {
                let mut weather_page = WeatherPage::new();
                weather_page.bind_event().await;
                weather_page.run(spawner).await;
                self.back().await;  // 返回后重新绑定主菜单事件
            }
            ECalendarPage | EStockPage | EImageListPage | ESettingPage | EDebugPage => { /* 同上 */ }
            // ...
        }
    }
}
```

主菜单共 7 项：电子书、天气、日历、股票、图片、设置、调试。路由器还负责"恢复现场"：

- 冷启动进入配置的默认主页（`read_default_page()`，存 NVS，设置页可改：电子书/天气/日历/股票/主界面）；
- 深睡唤醒回到上次所在页（rtc_fast 的 `PAGE_INDEX`，IO 唤醒丢失时从 NVS 哨兵恢复）；
- 焦点与自动打开的应用保持一致：返回主界面后停留在该应用图标上，而非回到第 0 个。

页面生命周期：

```
MainPage.run()
  │
  ├── current_page == None → 渲染主菜单
  │
  └── current_page == Some(index)
        │
        创建子页面 → bind_event() → run() → 返回
        │
        back() → clear() + 重新绑定主菜单事件
```

### 5.3 事件绑定与清理

每次进入子页面时，先清除上一个页面的事件监听，再绑定新的事件：

```rust
// src/pages/setting_page.rs（典型模式，各页面一致）
async fn bind_event(&mut self) {
    event::clear().await;  // 清除所有非常驻监听
    event::on_target(EventType::KeyShort(1), Self::mut_to_ptr(self), |info| { ... }).await;
    event::on_target(EventType::KeyShort(2), Self::mut_to_ptr(self), |info| { ... }).await;
    event::on_target(EventType::KeyShort(3), Self::mut_to_ptr(self), |info| { ... }).await;
}
```

`clear()` 只清除 `fixed: false` 的监听器；`on_fixed` 注册的常驻监听器跨页面保留。事件本身走队列化派发：按键扫描任务（`event::run`）只产出事件入队（容量 8，队满丢最旧），`dispatch` 任务串行派发到监听回调——长回调期间按键不丢。派发期间持有监听表锁且回调串行执行，回调内禁止再调 `on/clear` 重绑定（会死锁），重绑定由页面 `run` 循环在派发之外完成。

### 5.4 股票页面：两种视图与交易时段感知

股票页（`pages/stock`）是一个数据密集型页面，几个设计点值得单独说明。

**总览 + 明细两种视图**（`STOCK_VIEW` 存 rtc_fast，跨深睡恢复）：总览是一张 6 支股票的网格，每格画"前一日 + 今日"分时走势（左右分屏、竖虚线分隔）；确认后进入单支明细。总览数据来自 rtc_fast 的 `STOCK_MINUTE_CACHE`（6 × 96 槽收盘价 + 昨收，约 1.3KB）——深睡唤醒重启后 DRAM 全丢，但这块缓存还在，30 秒内重复进入总览直接用缓存渲染，不重复拉取。退出页面时视图复位为总览。

**六种图模式环形切换**（`model/stock.rs::ChartMode`）：分时 → 日K → 周K → 月K → 折线 → 行情盘口 → 分时。其中"日K"与"折线"共用同一数据源（`scale=240`），两者互切时不重新请求，只换渲染方式；其余跨源切换才重新拉取。当前模式编码成一个 `u8` 存进 rtc_fast（`STOCK_MODE`），深睡唤醒后恢复，保证分时模式"每 2 分钟唤醒刷新"的周期不被重置。

**拉取移出按键回调**：按键回调里只置标志（`need_fetch` / `need_clean_render`），真正的网络请求在 `run()` 循环里执行——这样拉取期间按键仍能响应。切换股票/模式时**不清空旧数据**，拉取期间继续显示上一张图（参考天气页），新数据回来后再替换。

**两种数据源 + 两种解析器**：K 线走新浪 `CN_MarketData.getKLineData`（明文 HTTP），实时盘口走腾讯 `qt.gtimg.cn`。新浪返回的是 JSON，但 `parse_kline` **故意不用 mini_json**——60 根 × 6 字段会让 mini_json 分配 12~15KB 堆（64KB 堆下会 OOM），所以改用零分配的字节扫描器直接填 `heapless::Vec`。腾讯返回是 GBK 编码、`~` 分隔，`split_gbk_tilde` 会按 GBK lead byte 跳过次字节，避免把 GBK 尾字节 `0x7E` 误判成分隔符。

**定时刷新周期由交易时段决定**（节假日感知）：

```rust
// src/pages/stock/page.rs:591-606（简化）
let realtime = self.view == StockView::Overview || self.mode.is_realtime();
let sleep_secs: u64 = if !realtime {
    12 * 3600                              // 日K/周K/月K：12 小时
} else {
    match crate::worldtime::get_clock() {
        Some(clock) => {
            let now = clock.local().await;
            if market_open_now(&now, holidays.as_ref()) {
                120                        // 开盘：每 2 分钟唤醒刷新
            } else {
                secs_until_next_open(&now, holidays.as_ref())  // 睡到下一开盘
            }
        }
        None => 120,                       // 无时钟源无法判断，维持原频率
    }
};
```

`market_open_now` 判定交易日 9:15~11:31 / 12:55~15:01（周一~五，holiday-cn 已同步时按其修正休市/调休）；`secs_until_next_open` 在非开盘时段直接算出距下一开盘的秒数——午休睡到 12:55，收盘后/周末/节假日睡到次交易日 9:25，不空转刷新。空闲入睡阈值复用配置的"天气睡眠时长"。

按键布局也按视图分流：总览（短按 1/2 移动选中格、长按 1 强制刷新、短按 3 进明细、长按 3 返回主界面）；明细（短按 1/2 切换图模式、长按 1/2 切换股票、短按 3 重新拉取、长按 3 返回总览）。

渲染上，蜡烛图/折线由 `widgets/kline.rs` 绘制（收≥开画空心、收<开画实心；屏幕放不下时只取最近若干根，保证每根 ≥7px）。行情盘口则用表格布局画出基本信息与买卖五档。

### 5.5 阅读页面：菜单、书签与书单

阅读页（`pages/read/page.rs`）是本项目最大的页面（近 3000 行）。它运行在独立的"重启分模式"里（见第 7 篇 1.7）：不初始化 WiFi，整块堆让给 TTF 渲染。UI 层面有四个值得展开的状态机。

**阅读菜单 9 项**（`MENU_ITEMS`）：返回书单 / 书签 / 跳转进度 / 排版 / 字体 / 旋转屏幕 / 方向键互换 / 睡眠 / 取消。菜单是一个叠层面板，画在正文之上。所有交互状态收敛到一个枚举：

```rust
// src/pages/read/page.rs:117-128
enum MenuState {
    Closed,
    Popup { menu_index: u32 },                    // 主菜单
    JumpInput { input_pct: u8 },                  // 跳转进度（百分比输入）
    /// 排版：cursor 0=字号 1=行距 2=笔画 3=重置 4=返回；editing=true 时上下键改值
    Layout { cursor: u8, editing: bool },
    FontList { font_index: u32 },                 // 字体列表（SD 的 TTF + 3 个内置点阵）
    /// 书签列表：bm_index 0=收藏书签 1..=n=书签 n+1=取消
    BookmarkList { bm_index: u32 },
    /// 书签操作弹层：action 0=打开 1=删除
    BookmarkAction { bm_index: u32, action: u32 },
}
```

渲染据此做增量优化：`menu_state_id()` 给每个状态编号，只有跨状态切换（面板几何不同）或正文真变了（旋转/改字号行距）才清屏重绘正文；同状态内移动光标只重绘叠层——跳过 SD 读 + TTF 光栅化，菜单操作明显更流畅。叠层面板自带白色填充，重画时自擦除上一帧内容。

**书签**：书签列表态 + 操作弹层两级。列表首行固定"收藏书签"（确认即把当前进度写入 .log），其后列出已有书签，末行取消；选中某个书签确认后进入"打开/删除"两行弹层。选中行会加载预览——从 SD 书签偏移处读 512 字节，截去前后不完整的 UTF-8 序列后显示（512 % 3 = 2，中文几乎必然截在多字节字符中间，不截边界 `from_utf8` 会整段失败）。打开书签即跳转到记录的字节偏移（bit31 是"已到末页"标记，低 31 位才是偏移）。

**书单二级目录**：`books/` 根层列出子目录与书，进入子目录后首行变"..返回上级"。目录层级与书下标都记在 rtc_fast（`LIST_SUBDIR`/`LIST_BOOK_IDX`）：下次普通进入书单时恢复到上次打开的书所在目录并选中它；续读则由 `RESUME_SUBDIR` 恢复目录。换层用 `change_dir` 原位换目录（自动关旧句柄），返回上级经 SD 根重开 `books/` 释放目录槽位。

**方向键互换**：阅读功能内（翻页/菜单/跳转/排版/字体/书签/书单）Key1/Key2 的方向整体对调。实现上极薄——`bind_event` 把两条物理键的 `down` 取值按 `swap_keys` 对调后交给统一的 `dir_key_short/dir_key_long`：

```rust
// src/pages/read/page.rs:2949-2957
// Key1 short: 向下 / +1 / 下一页 / 下一本（“方向键互换”开 → 向上）
event::on_target(EventType::KeyShort(1), Self::mut_to_ptr(self), move |info| {
    Box::pin(async move {
        let mut_ref: &mut Self = Self::mut_by_ptr(info.ptr).unwrap();
        let down = !mut_ref.swap_keys;      // 互换开 → Key1 变"向上"
        mut_ref.dir_key_short(down).await;
    })
}).await;
```

开关状态存 flash（`ReadingFlagsStorage`，magic "PGSW"），跨重启保留。排版菜单（字号/行距/笔画加粗/重置/返回）同理：编辑态上下改值、长按连发，确认或返回时把 `ttf_px/line_gap/rotate/font_name` 打包写进 flash 的 `ReadingSettings`。

### 5.6 设置页面：列表菜单与编辑态

设置页（`pages/setting_page.rs`）用 `ListWidget` 承载 11 项设置，三种模式（`SettingMode`）：二维码（web 配网）、设置列表、自动定位。列表项：阅读睡眠 / 天气睡眠 / 自动定位 / web配置 / 股票 / 默认主页 / 全刷次数 / 网络对时 / 更新节假日 / 时间显示 / 返回。

交互统一为"选中 → 确认进入编辑态（条目显示 `>>值<<`）→ 上下改值 → 确认保存"：睡眠时长步进 5 秒（阅读最小 10 秒）、股票在已配置列表内循环、默认主页在五个取值间循环、全刷次数 1~100（保存后立即 `reload_full_refresh_times` 生效）。"网络对时"触发一次手动 NTP + 写 PCF8563，"更新节假日"重拉 holiday-cn，两项都在条目上显示上次成功的时间戳（NVS 持久化）。web 服务任务只在二维码界面运行，切走即停。

页面 run 循环里每轮 `reset_render_times()`——设置界面始终快刷，防止到达全刷阈值时列表突然闪烁；长按 1/2 做列表导航连发（400ms 节流）；二维码界面长按左键 10 秒重置设备（清 NVS + 软复位）。

### 5.7 天气与日历页面：待机渲染与分钟对齐

天气/日历页共享一套"低信息密度待机渲染"：进入页面时 `set_sleep_renderer(Some(sleep_renderer))` 注册一个精简版布局函数，系统睡眠前 `show_sleep()` 会调用它画待机帧（而不是完整版页面），让睡眠画面更清爽。页面 run 循环里还等待 AHT20 室内温湿度首采（v2 板 I2C 传感器，正常 ~300ms，上限 2s）才渲染首帧——定时唤醒的"刷完立刻睡"不会睡在缺数据的帧上。定时唤醒周期按"时间显示开→对齐下一分钟边界，关→睡到天气数据过期"计算（见第 7 篇 5.3）。

## 6. 条件编译适配不同屏幕

不同尺寸的屏幕需要不同的 UI 参数。通过条件编译在编译期确定：

```rust
// src/epd2in9_txt.rs:5-24
#[cfg(feature = "epd2in9")]
const LINES_NUM: u32 = 7;      // 2.9 寸：7 行文字
#[cfg(feature = "epd2in9")]
pub const WIDTH: u32 = 296;
#[cfg(feature = "epd2in9")]
pub const HEIGHT: u32 = 128;

#[cfg(feature = "epd4in2")]
const LINES_NUM: u32 = 22;     // 4.2 寸：22 行文字
#[cfg(feature = "epd4in2")]
pub const WIDTH: u32 = 300;
#[cfg(feature = "epd4in2")]
pub const HEIGHT: u32 = 400;

#[cfg(feature = "epd2in7")]
const LINES_NUM: u32 = 9;      // 2.7 寸：9 行文字
#[cfg(feature = "epd2in7")]
pub const WIDTH: u32 = 264;
#[cfg(feature = "epd2in7")]
pub const HEIGHT: u32 = 176;
```

屏型（epd2in9/epd2in7/epd4in2）与板型（board_v1/board_v2）各自三/二选一，`board/mod.rs` 里用 `compile_error!` 强制守卫，一台设备 = epd + board 的编译期组合。这种编译期适配没有运行时开销——未选中的代码根本不会编译。

## 小结

| 技术点 | 要点 |
|--------|------|
| Drawable trait | 组件与绘制目标解耦，可复用 |
| 纯几何图标 | 无图片资源，适合电子墨水屏 |
| Page trait | 统一的页面接口：new/render/run/bind_event + 裸指针回传 |
| 页面路由 | MainPage 作为路由器，match 分发到子页面；阅读走重启分模式 |
| 事件绑定 | 进入页面时 clear + on_target 绑定；事件队列化派发，长回调不丢键 |
| 叠层菜单 | MenuState 状态机 + 状态 id 判重，光标移动只重绘叠层 |
| 条件编译 | 编译期适配三种屏幕 + 两代板型 |
| 裁剪区域 | embedded-graphics clipping 限制绘制范围 |

在极低分辨率下，UI 设计的核心是**信息密度和可读性**——每个像素都要有意义。组件化让不同页面可以复用相同的 UI 构建 blocks，而 Page trait 保证了统一的生命周期管理。
