# 第 6 篇：数据持久化与文件系统

> English: [en/06-persistence-and-file-system.md](en/06-persistence-and-file-system.md)

> 用 Rust 构建ESP32-C3 电子墨水屏阅读器 · 系列文章

## 引言

嵌入式设备需要在断电后保存数据——WiFi 配置、天气缓存、阅读进度、排版设置、错误日志，甚至"当前时间"本身。在 PC 上你可能会用 SQLite 或文件系统，但在只有 4MB Flash 的 ESP32-C3 上，每一字节都要精打细算。

本项目使用三套存储方案：ESP32 内部 Flash 的 NVS 分区用于配置数据，MicroSD 卡通过 SPI 用于大容量存储（电子书、图片、阅读进度），再外加一颗 PCF8563 硬件 RTC（CR2032 备电池走时）保存时间。本文将深入它们的实现细节。

## 1. Flash 存储：零拷贝序列化

### 1.1 Flash 访问接口

ESP32 的 Flash 通过 `esp-storage` crate 访问，它实现了 `embedded_storage` 的 `ReadStorage` 和 `Storage` trait：

```rust
// src/storage.rs:11-40
pub fn write_flash(flash_addr: u32, bytes: &[u8]) -> Result<(), FlashStorageError> {
    let flash = unsafe { esp_hal::peripherals::FLASH::steal() };
    let mut flash = FlashStorage::new(flash);
    let result = flash.write(flash_addr, bytes);
    // Err 时 println 打印 "save fail" 后原样返回
    match result { Ok(_) => Ok(()), Err(e) => { println!("save fail：{:?}", e); Err(e) } }
}

pub fn read_flash(flash_addr: u32, bytes: &mut [u8]) -> Result<(), FlashStorageError> {
    let flash = unsafe { esp_hal::peripherals::FLASH::steal() };
    let mut flash = FlashStorage::new(flash);
    let result = flash.read(flash_addr, bytes);
    match result { Ok(_) => Ok(()), Err(e) => { println!("read fail：{:?}", e); Err(e) } }
}
```

`FLASH::steal()` 是 esp-hal v1.x 新增的 API——它绕过所有权系统直接获取 Flash 外设的引用。之所以可以这样做，是因为 Flash 操作不需要像 SPI 那样的独占访问（它使用内部总线），而且整个程序只有一处操作 Flash。

### 1.2 零拷贝序列化

本项目使用一种极其简洁的序列化方案——直接将结构体的内存表示写入 Flash：

```rust
// src/storage.rs:43-49
fn serialize_storage<T>(storage: &T) -> [u8; size_of::<T>()] {
    unsafe { ptr::read(storage as *const _ as *const [u8; size_of::<T>()]) }
}

fn deserialize_storage<T>(data: &[u8]) -> T {
    unsafe { ptr::read(data.as_ptr() as *const T) }
}
```

`serialize_storage` 把结构体的内存字节直接重解释成 `[u8; N]`，`deserialize_storage` 反过来。本质就是把结构体的原始内存字节读出来直接写 Flash，用 `ptr::read` / 指针重解释实现。

**优点**：零堆分配、零拷贝、极快的序列化速度。
**限制**：结构体的内存布局必须与 Flash 中的一致。如果修改了结构体定义（增减字段、改变类型），Flash 中的旧数据就无法正确反序列化。

### 1.3 存储布局

NVS 分区（0x9000 起始）被划分为连续的存储块，每个块存放一种数据：

```rust
// src/storage.rs（基准 NVS_OFFSET = 0x9000，顺序紧邻，靠 size_of::<前一结构>() 累加）
const VERSION_STORAGE_OFFSET = NVS_OFFSET + 0x00;
// VersionStorage { version: u32, init_tag: u32 }

const WIFI_STORAGE_OFFSET = VERSION_STORAGE_OFFSET + size_of::<VersionStorage>();
// WifiStorage { wifi_ssid: String<32>, wifi_password: String<64>, wifi_finish: bool }

const WEATHER_STORAGE_OFFSET = WIFI_STORAGE_OFFSET + size_of::<WifiStorage>();
// WeatherStorage { token: String<64>, city: String<32>, sync_time_second: u64, weather_data: Option<DailyResult> }

const SLEEP_STORAGE_OFFSET = WEATHER_STORAGE_OFFSET + size_of::<WeatherStorage>();
// SleepStorage { read_sleep_seconds: u64, weather_sleep_seconds: u64 }

const OTHER_STORAGE_OFFSET = SLEEP_STORAGE_OFFSET + size_of::<SleepStorage>();
// OtherStorage { data: String<64> }   // 复用：首字符存默认主页(0=电子书/1=天气/2=日历/3=股票/9=主界面)

const HOLIDAY_OFFSET = OTHER_STORAGE_OFFSET + size_of::<OtherStorage>();
// HolidayStorage { token: String<64>, sync_time_second: u64, holiday_response: Option<HolidayResponse> }

const ERROR_LOG_OFFSET = HOLIDAY_OFFSET + size_of::<HolidayStorage>();
// ErrorLogStorage { error_count: u32, last_error: String<200> }

const STOCK_STORAGE_OFFSET = ERROR_LOG_OFFSET + size_of::<ErrorLogStorage>();
// StockStorage { entries: [StockEntry; 6], count: u8, selected: u8 }
//   StockEntry { code: String<16>, name: String<32> }

const DISPLAY_STORAGE_OFFSET = STOCK_STORAGE_OFFSET + size_of::<StockStorage>();
// DisplayStorage { full_refresh_times: u32 }   // 0 = 未配置，display 侧 clamp 到平台默认

const READING_SETTINGS_OFFSET = DISPLAY_STORAGE_OFFSET + size_of::<DisplayStorage>();
// ReadingSettings { ttf_px: u8, line_gap: i8, rotate: u8, font_name: [u8; 32] }
//   默认：20 / 1 / 0 / "font.ttf"；进书时读取并 clamp（px 12..=40、gap ±10、rotate %4）

const SYNC_STAMP_OFFSET = READING_SETTINGS_OFFSET + size_of::<ReadingSettings>();
// SyncStampStorage { magic: u32 /*"SYND"*/, time_sync_sec: u64, holiday_sync_sec: u64, show_time: u8 }
//   手动对时 / 节假日更新的时间戳 + 天气/日历页时间显示开关（占用已移除的 ADC 校准槽）

const SLEEP_PAGE_OFFSET = SYNC_STAMP_OFFSET + size_of::<SyncStampStorage>();
// SleepPageStorage { magic: u32 /*"PAGE"*/, page: i32 }
//   睡前最后所在页：-1..=6 为网格页索引，哨兵值 100 = 阅读模式（深睡/断电后恢复现场）

const READING_FLAGS_OFFSET = SLEEP_PAGE_OFFSET + size_of::<SleepPageStorage>();
// ReadingFlagsStorage { magic: u32 /*"PGSW"*/, swap_keys: u8 }   // 阅读方向键互换

const STROKE_CONFIG_OFFSET = READING_FLAGS_OFFSET + size_of::<ReadingFlagsStorage>();
// StrokeConfigStorage { magic: u32 /*"STKE"*/, weight_x10: u8 }   // 笔画加粗 ×10，10..=30
```

每个存储块的偏移量是前一个块的偏移量加上其大小——一种简单但有效的顺序分配。后续新增的类型（`StockStorage`、`DisplayStorage`、`ReadingSettings`……直到 `StrokeConfigStorage`）一律**追加在末尾、不动既有结构**——既有数据不偏移、不丢失，因此始终不需要改 `INIT_TAG`。

新增块读取时还面临"Flash 从未写过、读出全是 0xFF/乱码"的问题，两种对策：

- **带 magic 的块**（`SyncStampStorage`/`SleepPageStorage`/`ReadingFlagsStorage`/`StrokeConfigStorage`）：读取后校验魔数，无效则按默认值处理（如 `read_stroke_weight()` 读到非法 magic 或越界系数一律返回 10）；
- **不带 magic 的块**（如 `DisplayStorage`、`ReadingSettings`）：由使用方把字段 clamp 到合法区间（越界回退默认值），`StockStorage::default` 填 6 个空条目。

写入侧同样讲究：`write_sleep_page()` 在值未变化时跳过写入，减少 Flash 磨损。

### 1.4 impl_storage! 宏

为了避免为每种存储类型重复实现读写方法，项目定义了一个宏：

```rust
// src/storage.rs:83-103
macro_rules! impl_storage {
    ($type:ty, $offset:expr) => {
        impl NvsStorage for $type {
            fn read() -> Result<Self, FlashStorageError> {
                let mut buffer = [0u8; size_of::<Self>()];
                read_flash($offset as u32, &mut buffer)?;
                Ok(deserialize_storage(&buffer))
            }
            fn write(&self) -> Result<(), FlashStorageError> {
                let data = serialize_storage(self);
                write_flash($offset as u32, &data)
            }
        }
    };
}

// 一行代码为类型实现读写
impl_storage!(VersionStorage, VERSION_STORAGE_OFFSET);
impl_storage!(WifiStorage, WIFI_STORAGE_OFFSET);
impl_storage!(WeatherStorage, WEATHER_STORAGE_OFFSET);
impl_storage!(SleepStorage, SLEEP_STORAGE_OFFSET);
// ... Other / ErrorLog / Stock / Display / ReadingSettings / SyncStamp /
//     SleepPage / ReadingFlags / StrokeConfig 共 13 个
```

`NvsStorage` trait 定义了统一的读写接口：

```rust
pub trait NvsStorage {
    fn read() -> Result<Self, FlashStorageError> where Self: Sized;
    fn write(&self) -> Result<(), FlashStorageError>;
}
```

唯一的例外是 `HolidayStorage`——它手动实现 `NvsStorage`，写入走分块（见 1.5）。

### 1.5 分块写入：解决栈溢出

`HolidayStorage` 包含一个较大的 `HolidayResponse` 结构体，整体序列化可能超过栈空间。项目为此实现了分块写入：

```rust
// src/storage.rs:52-74
fn write_storage_chunked<T>(storage: &T, offset: u32) -> Result<(), FlashStorageError> {
    const CHUNK_SIZE: usize = 128;  // 每次只处理 128 字节
    let total_size = size_of::<T>();
    let storage_ptr = storage as *const T as *const u8;

    for chunk_offset in (0..total_size).step_by(CHUNK_SIZE) {
        let chunk_size = core::cmp::min(CHUNK_SIZE, total_size - chunk_offset);
        let mut chunk = [0u8; CHUNK_SIZE];  // 固定大小的栈缓冲区

        unsafe {
            ptr::copy_nonoverlapping(
                storage_ptr.add(chunk_offset),
                chunk.as_mut_ptr(),
                chunk_size
            );
        }
        write_flash(offset + chunk_offset as u32, &chunk[..chunk_size])?;
    }
    Ok(())
}
```

关键点：无论结构体多大，栈上始终只分配 128 字节的缓冲区。通过循环逐块写入，避免了 `serialize_storage` 中 `[u8; size_of::<T>()]` 在栈上分配大数组的风险。`HolidayStorage` 只有 `write()` 走分块，`read()` 仍是整块读（读方向的缓冲是调用方的局部变量，尺寸固定，风险可控）。

### 1.6 版本检查与初始化

启动时检查 Flash 中的初始化标记，如果不存在或不匹配则重新初始化所有存储区域：

```rust
// src/storage.rs:470-485
pub async fn enter_process() {
    let version_storage = VersionStorage::read();
    match version_storage {
        Ok(v) => {
            if v.init_tag != INIT_TAG {  // 0x1234_abce
                init_storage_area();     // 结构体变更后需要更新 INIT_TAG
            }
            let wifi = WifiStorage::read().unwrap();
            WIFI_INFO.lock().await.replace(wifi);
        }
        Err(_) => {
            init_storage_area();  // 首次启动
        }
    }
}
```

`INIT_TAG` 是一个魔数常量。每次修改存储结构体后需要更改这个值，这样下次启动时会检测到不匹配并重新初始化。`init_storage_area()` 会把整条链逐一写默认值（`SleepStorage` 默认阅读睡 120 秒、日历睡 5 秒；`ReadingSettings` 默认 20px/行距 1/font.ttf……），而带 magic 的 `SleepPageStorage`/`ReadingFlagsStorage`/`StrokeConfigStorage` 不在其中——它们靠 magic 校验自愈，无需显式初始化。

## 2. SD 卡文件系统

### 2.1 挂载与类型抽象

SD 卡通过 SPI 总线使用 `embedded-sdmmc` crate 操作。为了简化泛型，项目预定义了类型别名：

```rust
// src/sd_mount.rs:31-37
pub type SdCsPin = Output<'static>;
pub type ActualSpi = CriticalSectionDevice<'static, Spi<'static, esp_hal::Blocking>, SdCsPin, NoDelay>;
pub type ActualSdCard = SdCard<&'static mut ActualSpi, Delay>;
pub type ActualVolumeManager = VolumeManager<ActualSdCard, TimeSource>;
pub type ActualVolume<'a> = Volume<'a, ActualSdCard, TimeSource, 4, 4, 1>;
pub type ActualDirectory<'a> = Directory<'a, ActualSdCard, TimeSource, 4, 4, 1>;
pub type ActualFile<'a> = File<'a, ActualSdCard, TimeSource, 4, 4, 1>;
```

泛型参数 `4, 4, 1` 分别是最大卷数、最大打开目录数、最大打开文件数。在资源受限环境中，这些参数需要精心控制。

SD 卡在 `main.rs` 中挂载后存入全局 Mutex：

```rust
// src/main.rs:287-304
let sdcard = SdCard::new_with_options(spi_bus_sd, embassy_time::Delay, AcquireOpts {
    use_crc: false,           // 关闭 CRC 校验（某些卡不兼容）
    acquire_retries: 50,      // 初始化重试 50 次
});
let volume_mgr = VolumeManager::new(sdcard, crate::sd_mount::TimeSource);
let sd_mount = SdMount::new(volume_mgr);
SD_MOUNT.lock().await.replace(sd_mount);
// SD 上电后要通信一次，不然对显示通信有干扰
if let Some(ref mut sd) = *SD_MOUNT.lock().await {
    match sd.volume_manager.open_volume(embedded_sdmmc::VolumeIdx(0)) {
        Ok(_) => println!("[sd] volume open ok"),
        Err(e) => println!("[sd] open_volume fail: {:?}", e),
    }
}
```

`TimeSource` 返回全零时间戳——FAT 时间戳字段合法即可，设备没有可用的实时钟写进 SD（虽然 PCF8563 有时间，但没有为它实现 `TimeSource` 适配）。

### 2.2 长文件名（LFN）支持

中文书名远超 FAT 的 8.3 短名限制，LFN 是刚需。上游 `embedded-sdmmc` 长期只支持 LFN **读取**、不支持**创建**，所以本项目直接使用自己的 fork：

```toml
# Cargo.toml
embedded-sdmmc = { git = "https://github.com/longxiangam/embedded-sdmmc-rs", branch = "lfn-create" }
```

fork 在库内补齐了 LFN 目录项的写入（生成带 `~` 的唯一短名 + 构建 UTF-16LE 的 LFN 条目 + 校验和），对外只暴露一个朴素的新 API：

```rust
// src/sd_mount.rs:299-315
/// 按长文件名打开/创建文件（如 "三体.log"）——LFN 创建由 fork 版库内完成

    mode: Mode,

        .open_long_name_file_in_dir(&log_lfn, mode)
        .map_err(|_| SdError::FileNotFound)
}

/// 纯长文件名打开（上传电子书/图片时用）
pub fn open_file_by_name<'a>(books_dir: &'a mut ActualDirectory, file_name: &str,
                             mode: Mode) -> Result<ActualFile<'a>, SdError> {
    books_dir.open_long_name_file_in_dir(file_name, mode).map_err(|_| SdError::FileNotFound)

```

早期版本曾在应用层手写三个阶段的 LFN 写入（扫描目录生成 `BK0001~1.TXT` 短名 → 用短名建文件让 FAT 分配簇 → 直接改写目录扇区插入 LFN 条目），迁入 fork 后这部分代码全部删除，应用层只剩业务逻辑。

**读取**侧用库自带的 `iterate_dir_lfn` + `LfnBuffer`（512 字节栈缓冲）遍历目录，一次回调里同时拿到短名条目和长名字符串：

围绕它还有一组目录/文件工具：

## 3. 阅读数据持久化：.log 与续读

### 3.1 从 .idx 到 .log

最早的阅读器是"点阵字体 + 预分页"：打开书时扫描全文，把每页的字节偏移写进 `.idx` 索引文件（一个 `u32` 数组），翻页时按需加载。随着阅读器切换到 TTF 矢量字体（字号/行距/字体文件都可调，第 10 篇），预分页失去前提——排版参数变了页界就全变了。现在的分页是**字节偏移 + 实时排版**，不再需要 `.idx`；持久化下来的只剩"读到哪了"，即 `.log` 文件。

### 3.2 .log 文件格式与 TxtReader

`.log` 用书的长名命名（`三体.log`），内容是一个大端 `u32` 数组：

- `[0]`：上次阅读的字节偏移；
- `[1..]`：书签的字节偏移（最多 100 个，去重）。

读写逻辑集中在 `src/epd2in9_txt.rs` 的 `TxtReader`：

```rust
// src/epd2in9_txt.rs:61-99（save_log 节选）
/// is_favorite=true 追加书签（去重），否则更新 [0]（上次阅读位置）
pub fn save_log(my_file: &mut FileObject, log_vec: &mut Vec<u32, LOG_VEC_MAX>,
                page: u32, is_favorite: bool) {
    if is_favorite {
        // 只查书签区（索引 1 起），不与"上次位置"去重
        let already = log_vec.iter().skip(1).any(|&p| p == page);
        if !already && log_vec.len() < LOG_VEC_MAX { log_vec.push(page); }
    } else if log_vec.len() == 0 {
        log_vec.push(page);
    } else {
        log_vec[0] = page;
    }
    // 逐个 u32 按 大端 序写回 SD
}
```

配套常量也定义在这里：`LOG_VEC_MAX = 100`（书签上限）、`PAGES_VEC_MAX = 1000`、`ONE_PAGE_CONTENT_LEN = 2000`（单页文本缓冲字节数），以及按屏型 feature 选择的 `WIDTH/HEIGHT/LINES_NUM`。书单页还会批量读每本书的 `.log[0]`，在书名旁渲染"读到 32%"之类的进度。

翻页/跳转/退出阅读的各个路径都会写 `.log[0]`（`save_log_raw` 原样写回整个 Vec），保证随时拔卡断电最多丢当前页。

### 3.3 跨深睡续读链路

"合上盖子明天接着读"靠三层数据配合：

1. **rtc_fast（跨深睡、不跨断电）**：`READING_MODE`（本次启动是否直接进阅读）、`TTF_RESUME_OFFSET`（当前书的字节偏移）、`LIST_SUBDIR/LIST_BOOK_IDX`（书单目录与光标）。深睡唤醒后从这里秒恢复，不碰 SD；
2. **NVS `SleepPageStorage`**：页面变化时写 `page`（哨兵值 100 = 阅读模式）。IO 唤醒等极端情况下 rtc_fast 会丢，main 启动时从 NVS 判断"上次在阅读"，直接走阅读重启分支（不初始化 WiFi）；
3. **SD `.log[0]`**：冷启动打开书时，从 `.log[0]` 恢复上次阅读位置（夹到文件长度内）；若 rtc_fast 里有更新的 `TTF_RESUME_OFFSET`（深睡续读），则以后者为准、跳过 `.log[0]`。

三层兜底的结果：深睡续读不读卡、断电重启回到上次在看的书和位置。

## 4. 时间的持久化：PCF8563 硬件 RTC

### 4.1 I2C 总线封装

v2 新板挂了一条 I2C 总线（GPIO9=SDA / GPIO21=SCL，100kHz——PCF8563 的安全上限），上面有 AHT20 温湿度传感器（0x38）和 PCF8563 RTC（0x51）两个设备。总线被收进一个全局 Mutex，驱动统一通过 `i2c_bus.rs` 的助手函数访问：

```rust
// src/i2c_bus.rs
pub static I2C: Mutex<CriticalSectionRawMutex, Option<I2cDev>> = Mutex::new(None);

pub async fn write(addr: u8, data: &[u8]) -> Result<(), ()> { /* 锁总线 → dev.write */ }
pub async fn write_read(addr: u8, wr: &[u8], rd: &mut [u8]) -> Result<(), ()> { /* 写寄存器地址再读 */ }
```

旧板（board_v1）没有 I2C 外设，`init_i2c` 返回 None，PCF 相关调用自然短路。

### 4.2 PCF8563 读写

`pcf8563.rs` 把 PCF8563 当作系统时钟源：寄存器秒(0x02)/分/时/日/星期/月/年全部 BCD，时间以 **UTC** 存取（界面显示由 `Clock::local` 统一 +8h）：

```rust
// src/pcf8563.rs:27-47（read_time）
pub async fn read_time() -> Option<i64> {
    let mut b = [0u8; 7];
    i2c_bus::write_read(ADDR /*0x51*/, &[REG_SECONDS], &mut b).await.ok()?;
    if b[0] & 0x80 != 0 {
        return None;  // VL=1：备用电池掉过电/首次上电，内部时间不可信
    }
    // BCD 解码 + 合法性检查（月 1..=12、时 0..23 ...）
    // 组成 PrimitiveDateTime → Unix 秒（UTC）
}

pub async fn write_time(ts: i64) -> bool {
    // 1) 写 Control_1：STOP=1 暂停走时（防回滚撕裂）；失败即返回 false
    if i2c_bus::write(ADDR, &[0x00, 0x20]).await.is_err() { return false; }
    // 2) 从 0x02 秒寄存器起连写 7 个 BCD 寄存器
    let ok = i2c_bus::write(ADDR, &[REG_SECONDS, sec, min, hour, day, weekday, month, year]).await.is_ok();
    // 3) STOP=0 恢复走时
    let _ = i2c_bus::write(ADDR, &[0x00, 0x00]).await;
    ok
}
```

它同时是深睡定时唤醒源：倒计时定时器（`arm_timer_secs/minutes`，INT 脚拉低唤醒）与绝对时间报警（`arm_alarm_at`，PCF 用纽扣电池的 32k 晶振走时，比主控深睡慢时钟精确得多）都在这块芯片上——这部分在第 7 篇展开。

### 4.3 时间恢复链路：PCF 优先，rtc_fast 兜底

`worldtime.rs` 的 `ntp_worker` 在每次启动时按如下优先级恢复 `Clock`：

```rust
// src/worldtime.rs:392-415（节选）
#[embassy_executor::task]
pub async fn ntp_worker() {
    let clock = CLOCK_CELL.init(Clock::new());
    // 1) 优先从 PCF8563 恢复（备电池维持，权威）
    let restored = pcf_restore(clock).await;
    if !restored {
        // 2) 回退 rtc_fast 估算：睡前时间戳 + 深睡时长
        //    恢复值同样要做 2020..2100 sanity 检查，异常就等 NTP 重新对时
    }
    loop {
        // 距上次对时超过 3600s → use_wifi + ntp_request 对时
        // 3) 对时成功：更新 CLOCK_SYNC_TIME_SECOND，并把 UTC 写进 PCF8563
        //    + SyncStampStorage::write_time_stamp（手动对时记录）
        // 失败退避：连续失败 1s→10s，断网 10s→3600s
    }
}
```

`pcf_restore` 成功后还会把 rtc_fast 里的 `CLOCK_SYNC_TIME_SECOND` 一并补上——该标志在 IO 唤醒时会丢，不补的话天气页会误判"从未对时"、NTP 也会立刻空跑一次。这条链路落地后，阅读等无网模式（`init_clock_pcf`，PCF 是唯一时间源）、深睡漂移、换电池断电，都不再丢时间；股票页的跨天判断也不再因时间滞后出错。

### 4.4 SyncStampStorage：对时/节假日更新的持久记录

Flash 侧的 `SyncStampStorage`（magic `"SYND"`）记录三个字段：手动对时时间戳、节假日更新时间戳、天气/日历页时间显示开关。它是对时间的"元数据"持久化——设置页展示"上次对时：xx 天前"，以及 NTP 长期失败时判断数据新旧，都从这里读。PCF8563 与 `SyncStampStorage` 一个管"现在几点"，一个管"多久没对过时"，互为补充。

## 小结

| 技术点 | 要点 |
|--------|------|
| Flash 访问 | `esp-storage` + `FLASH::steal()` |
| 零拷贝序列化 | `ptr::read` 直接将结构体内存写入 Flash |
| 存储布局 | NVS 分区顺序分配 13 个块，新块只追加在末尾 |
| 魔数校验 | 带 magic 的块自愈，无 magic 的块靠 clamp 兜底 |
| 分块写入 | 128 字节分块避免栈溢出（`HolidayStorage`） |
| impl_storage! 宏 | 一行代码为类型实现读写 trait |
| SD 卡 | `embedded-sdmmc` fork（lfn-create 分支）+ SPI |
| LFN 支持 | `open_long_name_file_in_dir` 直接按中文长名建文件 |
| 阅读进度 | `.log` 文件：`[0]` 上次位置 + 书签数组，大端 u32 |
| 续读链路 | rtc_fast（深睡）→ NVS 页码（IO 唤醒）→ SD `.log`（断电） |
| 时间持久化 | PCF8563（CR2032 走时，UTC/BCD）+ `SyncStampStorage` |

核心思想：**在资源受限环境中，用最简单直接的方式解决持久化问题**。零拷贝序列化不是最优雅的方案，但它是最适合嵌入式环境的——快、小、省内存；而"每类数据挑最便宜的非易失介质"（配置进 Flash、大文件进 SD、时间进硬件 RTC）比把一种存储用到极限更有效。
